## 1. 页面总览与操作权限

| 页面 | 本环境入口 | 主要用途 | 能否改变生产行为 |
|---|---|---|---|
| OpenClash / LuCI | `http://10.88.0.254/` → 服务 → OpenClash | 运行状态、配置、规则、策略和日志 | 可以；更改模式、配置、规则、出口或重置连接均可能影响业务 |
| Metacubexd / Zashboard | 从 OpenClash 首页按钮进入 | 查看运行中的策略、节点、provider、连接和规则 | 可以；选择出口与关闭连接直接影响运行内核 |
| Kuma | `http://10.88.0.249:3101/` | 监控状态、响应时延和故障历史 | 查看不改路由；管理员可修改监控与通知 |
| 节点能力看板 | `http://10.88.0.249:3102/` | 节点评估、业务能力、结果时效和生产分流抽查 | 页面主要用于查看；后台既有业务控制器是否启用要分别核对 |
| 订阅管理页 | `http://10.88.0.249:3103/` | 查看公共来源及发布历史；添加自己的节点 | 公共状态只读；下方自建编辑器经独立认证可写 |
| DPanel / Docker | 使用 249 已有的管理入口 | 查看容器、挂载、端口和日志 | 停止、重建、删除卷可能同时影响中心内多个服务 |

OpenClash 本环境控制 API 为 `10.88.0.254:9090`，混合代理入站为 `10.88.0.254:7893`。API、代理、3103 编辑器和 provider 下载各有不同凭据，不能互相代用。代理端口不是普通管理网页。

管理网页可在局域网打开，不代表其连接已加密或编辑无需认证。访问凭据只在受信管理终端使用；完整订阅链接、节点分享链接、Cookie、控制密钥不放入 GitHub、截图或排障工单。远程管理沿用已验收的认证入口，不为看面板临时开放控制 API。

## 2. OpenClash 首页逐项说明

### 2.1 运行状态与版本

| 项目 | 含义 | 查看时需要注意 |
|---|---|---|
| Smart 运行中 / 内核状态 | 当前内核及其运行状态 | 不代表每个业务组都在用 Smart 类型，也不证明全部节点可用 |
| OpenClash 版本 | 插件及 LuCI 界面版本 | 与配置版本、安装器版本分别管理 |
| `alpha-smart-…` | Mihomo Smart 内核构建版本 | 有更新不等于可以直接替换；安装器及准入程序还会校验固定散列 |
| 覆写模块 | 配置生成阶段加载的覆写 | 本环境有 `dns-privacy` 等既有处理，不能只看源 YAML 推断最终运行配置 |
| 运行开关 / 重启 | 启停内核及相关处理 | 是生产操作，会中断或改变正在使用的连接 |

当前配置名为 `精准稳定-v1-r4-ha-subscription-managed.yaml`。源文件位于 `/etc/openclash/config/`，运行文件位于 `/etc/openclash/`；两者经过覆写后可能不同。验收以实际内核规则和连接记录为准。

### 2.2 运行模式与代理模式

| 区域 | 选项 | 用途及影响 |
|---|---|---|
| 运行模式 | 增强 / TUN / 混合 | 影响流量接管方式，涉及插件防火墙及内核配置；不用于临时修复某个网站 |
| 代理模式 | 规则 | 按当前运行规则逐条匹配 |
| 代理模式 | 全局 | 使用内核全局出口；不会继续按每个业务组分别分流 |
| 代理模式 | 直连 | 绕过代理出口；依赖代理访问的目标可能失败 |

本轮已验收的生产分流使用规则模式。切到全局或直连会使原来的业务分流观察失去可比性，排障时先记录当前模式，不要反复切换试错。

### 2.3 区域绕过、嗅探、DNS 代理和流媒体解锁

| 开关 | 主要作用 | 与结果的关系 |
|---|---|---|
| 区域绕过 | 对指定区域使用插件的绕过逻辑 | 可能让流量不再按预期进入业务规则；不等同于添加一条 DIRECT 域名规则 |
| 域名嗅探 | 从受支持的流量中补充域名信息 | 有助于域名分流，但不能保证识别所有应用、加密方式或下载地址 |
| DNS 代理 | 控制插件对应 DNS 功能 | 开关状态不能单独证明所有设备的 DNS 路径或无泄漏 |
| 流媒体解锁 | 插件的流媒体检测/处理功能 | 与 3102 的业务能力标签是不同模块；不代表账号、版权或播放一定正常 |

这些都是配置功能，不是“越多开启越快”。本手册介绍含义，不要求改变当前已验收组合。

### 2.4 配置文件卡片

| 项目 | 如何理解 |
|---|---|
| 文件名及时间 | 用于辨认配置及文件更新时间；不是供应商套餐到期时间 |
| 下拉框 | 选择配置文件；保存/应用或切换后可能改变整个运行图 |
| 覆写标签 | 表示关联的处理模块；与运行规则一起核对 |
| 订阅流量、到期时间 | 从订阅响应元数据获取，不是从节点数量或运行统计推算 |
| 无订阅信息 | 未取得可解析的套餐元数据；不等于 provider 没有节点或订阅一定失效 |

图标的动作以界面悬浮提示和弹窗为准。刷新页面、刷新套餐信息、下载订阅、切换配置是不同操作，不能因图标相似而互相替代。

当前受管配置已启用自动用量显示：每个启用的公共来源单独一张卡片，显示正常、等待、缓存或失败及最后成功时间。来源增删自动反映，不需要逐家再填信息地址。首次升级按 `Ctrl+F5` 刷新脚本；不要为恢复信息显示去切换业务策略或下载整份订阅。

机场名称优先尊重已有非通用自定义名称或 `display_name`，否则自动解析原始订阅标题及编码文件名。当前两家卡片已显示供应商返回的名称；未识别时会明确标注，不猜域名。该名称不修改内核 provider ID，详见[名称与 N 来源验收](subscription-usage-names-acceptance-20261027.md)。

### 2.5 运行数据

| 指标 | 含义 | 不能据此得出的结论 |
|---|---|---|
| 上传 / 下载速度 | 内核当前观察到的流量速率 | 不等于宽带套餐上限、节点最大带宽或全局所有设备总流量 |
| 上传 / 下载总量 | 当前内核统计口径下的累计值 | 不是机场账单；重启、重置及多出口会影响口径 |
| 连接 | 内核当前跟踪的连接数量 | 一个 App 可建多条连接，不能直接换算为在线设备数 |
| 内存 / CPU / 负载 | 界面对应的运行采样 | 单点偏高不能直接定位带宽、磁盘或 DNS 故障 |

首页 CPU/内存采样不是所有容器、虚拟机和主机存储的完整监控。有隔离检测进程时，应按完整启动参数区分生产内核与测试内核，不能只按 `clash_meta` 名字判断。

### 2.6 快捷操作

| 按钮 | 影响 |
|---|---|
| 关闭连接 | 关闭内核连接，可能打断下载、对话、播放、远程会话；不要用来刷新页面 |
| 重置防火墙 | 重新处理 OpenClash 相关防火墙规则，可能短时影响接管；不用于普通页面显示问题 |
| 清理 DNS 缓存 | 已读取实现会清理内核 DNS 和 fake-IP 缓存，可能触发重新查询；不会因此改变订阅账单或补齐节点 |
| 检查更新 | 查询更新状态；下载、升级和重启是另一个需要备份验收的动作 |

对单个业务排障优先新建该业务请求，再看对应连接；不要批量关闭其他业务长连接。

## 3. Metacubexd / Zashboard 的使用顺序

两者都连接当前 Mihomo 控制 API，界面布局可能不同，运行结果应相同。连接失败先核对 API 地址、凭据与局域网可达性，不通过关闭认证解决。

### 3.1 策略组与出口

1. 找到具体业务组，记录当前选项及其父组。
2. 按需要选择 DIRECT、REJECT、稳定自动、手动入口、国家池或专用池。
3. 如果选择的是另一个组，继续展开到最终节点；菜单显示的组名并非最终出口。
4. 新建请求，在连接页面核对域名、匹配规则和完整 `chains`，然后验证真实业务。

本环境 69 个业务组及 6 个指定功能选择组已补齐 `🛟 稳定自动`。这是可选入口，未把所有业务切到它；自定义、专用控制池和技术自动组不批量增加其他出口，避免循环或打破故障断流约束。

| 入口 | 行为 |
|---|---|
| 默认策略 / 父组 | 继承父组；更改父组会影响引用它的多个业务 |
| DIRECT | 由路由链路直接出站；仍受 DNS、运营商、目标站点等影响 |
| REJECT | 阻断命中的连接 |
| 稳定自动 / 自动选择 | 按组的实际类型、成员、探测目标及控制机制工作；名字本身不保证稳定或业务可用 |
| 国家 / 地区组 | 选择该地区池；节点名称不等于真实 IP 归属或账号可用地区 |
| 业务专用池 | 由对应业务机制维护；不能把普通延迟测试当作该业务登录验收 |
| `🔐 自定义节点` | 全局唯一、共用当前选择；选定出口故障时不自动跳到公共节点或 DIRECT |

### 3.2 节点与 provider 数量

节点详情、策略组菜单和 provider 列表显示的是不同集合。一个真实节点可出现在多个业务组中，不能把菜单数量相加；REJECT、DIRECT、策略组和空来源占位项也不是真实节点。

查看数量时依次核对：上游条目 → 过滤后节点 → 去重端点 → 已准入候选 → 当前发布 → 内核运行 provider。公共来源和 Local_Custom 分开计算。完整口径及本轮异常见[节点数量诊断](diagnostics-20261027.md)。

### 3.3 连接、规则与日志

| 页面 | 重点看什么 |
|---|---|
| 连接 | 请求时刻、源设备、域名/目标 IP、规则类型与载荷、完整出口链、失败原因 |
| 规则 | 规则顺序、目标策略是否存在；较早命中的共享域名规则可能先于具体业务组 |
| provider | 当前加载数、更新时间、更新错误及真实节点内容；区分节点 provider 与规则 provider |
| 日志 | 先取与出错时刻和目标相关的少量记录；HTML 403、429、TLS 错误和超时分别判断 |

只有目标 IP 的连接，不一定能仅凭地址判断应用归属；共享 CDN、DoH、连接复用及应用代理都可能改变观察方式。单独测试组可用，也不证明生产业务实际走了该组。

## 4. 首页 IP 地址与访问检查

PConline、IPIP.NET、IP.SB、IPify 等检测项访问不同目标，各自可能命中不同规则或使用不同地址族。结果是对应检测站看到的出口，不是全网唯一出口，也不等于某台终端网卡地址。

本次已读取的 OpenClash 实现由旁路由发起检测请求；不是只因为浏览器打开页面，就把结果当成浏览器自己的全部流量路径。缓存、不同检测时刻和节点变化也可能造成显示差异。

### 4.1 为什么显示 IPv6

代理链可以是“本地 IPv4 → 代理服务器 → 检测网站 IPv6”。关闭旁路由的 IPv6 接管或 DNS AAAA 返回，不代表代理服务器不能使用自己的 IPv6 出口。

本轮复现时，OpenClash `ipv6` 和 DNS `ipv6` 均为 false，旁路由无公网 IPv6 地址；使用本地 IPv4 查询仍获得检测站的 IPv6 结果。证据说明这次显示的是代理出口，不能据此认定局域网 IPv6 泄漏。详见[本轮 IPv6 取证](diagnostics-20261027.md)。

若要评估真正泄漏，需要分别验证终端 IPv6 地址/默认路由、实际 DNS 路径、IPv6 接管规则和目标连接；不要只改一个页面或关闭显示。

### 4.2 访问检查能证明什么

检测成功只说明对应请求达到了预期条件。首页成功不代表 App 登录、账户风控、流媒体播放、支付或大文件下载成功。网页慢时要记录首字节、总耗时及实际下载域名，不能只用一个延迟数值判断。

## 5. “无订阅信息”的解释与恢复思路

### 5.1 信息从哪里来

OpenClash 读取订阅 HTTP 响应的 `subscription-userinfo`，解析 `upload`、`download`、`total`、`expire` 等字段。节点文件可以正常加载，但没有这些元数据就无法显示套餐。

未接管的配置保留原生查找顺序：单独配置的 `subscribe_info` → 当前 YAML 的 `proxy-providers` URL → 与配置名称匹配的 `config_subscribe` 地址。本受管配置现在优先读取 249 的自动用量汇总，避免从节点发布文件倒推套餐来源；其他配置仍走原生逻辑。

### 5.2 本环境已确认的原因

初查时当前配置没有独立信息地址；两个公共 provider 来自 249，HTTP 200，但没有套餐头。因此“无订阅信息”是元数据链路缺失，和准入锁是两个独立问题。先前单来源绑定现已迁移为[自动多来源显示](subscription-usage-auto-20261027.md)，两家真实取数、LuCI HTTP 及页面显示均验收。节点发布 URL 没有被替换。

### 5.3 当前自动模式的日常维护

1. 沿用现有流程维护 3103 控制器的公共来源清单，新增、停用和删除自动反映到两处显示；此页面目前不是完整公共来源编辑器。
2. 页面约 30 秒刷新，正常用量约 10 分钟采集一次，失败单独退避。无需反复点击更新节点或切换配置。
3. 一家失败时查看它自己的原因；有历史显示缓存及时间，无历史显示未获取。其他成功来源继续显示。
4. 转换地址只有一个明确原始来源时自动解包；无法确定时，可在该来源清单项选填 `info_url`，保留节点 `url`。不将多个账户的用量或到期拼成一份虚假套餐。
5. 供应商不提供套餐头时到供应商管理页查询，自动显示不能创造不存在的账单数据。
6. 修改自动信息绑定、升级插件或撤销功能前，先看[对应双端备份及恢复命令](subscription-usage-auto-20261027.md)。不使用旧单来源事务覆盖当前配置。

自动模式只读中心缓存，不操作节点判断和业务出口；OpenClash 有少量元数据 Lua/JS 显示适配，主程序、节点下载地址、DNS 和当前业务选择未改。完整边界及插件升级注意事项见新事务记录。

已补上“转换”到**独立信息清单**的单向自动同步：保存后的地址约每 30 秒被 249 读取，用于名称、用量显示。页面会显示同步状态和最后成功时间。读取失败保留旧清单；明确空地址或停用只移除同步管理的条目，保留人工条目。只识别名称精确为“转换”的唯一条目，不自动读取其他配置。**节点发布清单仍独立，信息增加不触发节点发布。** 详见[最新操作、验收与回退](subscription-info-sync-20261027.md)。

### 5.4 订阅更新和容器重启后查看什么

17 项[隔离恢复验收](subscription-restore-acceptance-20261027.md)已完成，含实际重启与保留数据卷重建隔离容器；不是生产中心实际重启验收。

1. 核对启用来源是否都在，包括取数失败的来源；失败不应使该来源从清单消失，空来源也不应恢复旧卡片。
2. 看机场名称、用量和最后成功时间。刚重启读到新鲜缓存时可能显示“正常”，不证明本次已重新访问上游；最后成功时间不应被伪造为重启时间。
3. 名称与用量依赖来源清单、缓存、认证及启动挂载。缓存坏且上游离线时显示未获取是正确边界，等待上游和退避恢复；整卷或清单丢失则需核对备份，不能凭空补回。
4. 更新场景在隔离环境缩短了等待周期，生产仍按原周期运行。无需为刷新卡片关闭连接、重置防火墙、改 DNS 或切换业务策略。

全部 17 项、128 热缓存范围及未做的断电/生产重启等场景见[结果和恢复条件](subscription-restore-acceptance-20261027.md)。

## 6. Kuma（3101）

### 6.1 日常查看

1. 使用原 Kuma 账号进入页面，找到故障业务或相关分组。
2. 展开分组，确认具体哪个子监控 DOWN；“Child monitors down”不代表整个旁路由已停止。
3. 对齐故障时间，查看响应时延、错误、最近心跳及连续失败/恢复过程。
4. 区分 DNS、端口、主页、业务 API 与真实客户端；核对该监控实际使用的目标和出口。
5. 如故障已恢复，保留历史证据，再判断是否需要调整，不通过删除监控消除红色状态。

### 6.2 常见状态与操作

| 状态/操作 | 含义及影响 |
|---|---|
| UP / 正常 | 最近检查满足该监控条件；不保证所有业务能力 |
| DOWN / 故障 | 达到该项目失败判定条件，先读具体错误 |
| 重试 / 等待 | 仍在重试或尚无足够样本；以当前监控设置为准 |
| 暂停 | 不继续检查，不能把无新告警理解成已经恢复 |
| 编辑目标、间隔、超时、成功状态码 | 改变监控判定，不是在修复代理链路 |
| 通知设置 | 使用本实例已有通知配置；新增渠道或主动发送测试消息需要单独确认 |

监控间隔、重试次数和通知策略以当前监控详情为准。历史操作手册中的固定“30 秒/两次”等参数不能直接当成今天全部项目的设置。

Gemini 主页可能受地区或风控影响，与 Discovery/API 探针不是同一条件；Google 204 成功只覆盖该检测请求；Grok App、网页和其他客户端可能使用不同 API。403/429 应按响应内容及业务语义分类，不能全算健康或全算故障。

## 7. 节点能力与稳定性看板（3102）

### 7.1 各区域含义

| 区域 | 看什么 |
|---|---|
| 已评估 / 未评估 / 首轮预计剩余 | 调度进度；预计时间依赖实际耗时、排队与资源，不是承诺完成时间 |
| 节点状态卡 | 各状态节点数；应与活跃节点集合、结果年龄一起判断 |
| 业务能力概览 | 每项业务的可用数量；不同业务有不同判定，不是都跟随 AI 结果 |
| 当前生产分流验证 | 正常生产入口的业务抽查，与单节点隔离检测分开 |
| 业务质量卡 | 观察/自动优化、手动接管、首次成功率、慢请求比例和中位耗时；不是每个节点的统一评分 |
| 搜索与状态筛选 | 按节点/提供商搜索，缩小列表范围；筛选不会删除节点 |

页面实现每 30 秒刷新数据；刷新页面不会强制立刻重测所有节点。后台探测频率与页面刷新频率不同，不能频繁刷新来缩短调度。

### 7.2 节点行和状态解释

| 字段/状态 | 含义 |
|---|---|
| 节点 / 提供商 | 该评估记录的节点及来源；显示名称相同不保证是同一端点 |
| 评分 / 可信度 | 评分概括历史表现，可信度反映样本和连续表现；两者不是端到端成功概率 |
| HTTPS 耗时 | Clash 内真实节点的 HEAD 测速值；不含容器 API 往返开销，不等于下载速度或业务首字节耗时。失败显示“未取得” |
| 出口 | 最近获取的地区/出口信息，缺失或过期时不能靠节点名补齐 |
| 业务能力标签 | 各业务的结果；悬浮可看失败分类与该项可信度 |
| 最后检测 | 最近结果时刻；先核对本机及服务端时间，避免把旧结果当新结果 |
| 健康 | 该评估模型条件通过，不代表所有账号和网站可用 |
| 降级 | 表现不稳定或质量下降，需结合具体样本 |
| 业务受限 | 通用联网与部分业务结果不同，查看失败的业务标签 |
| 冷却观察 | 正在退避或等待复核，不应手动清空历史来“恢复健康” |
| 不可用 | 当前评估判定失败，按原因与时效复核 |
| 未评估 | 缺少足够检测结果，不等于已证实故障 |
| 数据过期 | 曾有结果但已超出有效期，不应继续作为新鲜能力证明 |

### 7.3 观察模式和自动控制

节点检测的后续维护已增加一小时冷却及自动复测：首次失败进入复核，三次独立失败确认，恢复需要两个独立成功样本；同一条 Clash 缓存不会重复计数。API 的 `health_schedule` 提供状态、下次复测时间和冷却截止时间，新口径 `latency_kind` 为 `Clash HTTPS HEAD`；尚未重测的旧记录为 `legacy_http`，附带真实样本的统计信息。检测设施故障单独处理，不是永久删除节点。详见[运行机制、验收和回退](node-health-coordination-20261028.md)。

通用能力评估器的 `shadow` 检测只操作获准的隔离检测入口，不负责切换生产业务组。现有业务质量控制器、ChatGPT 专用逻辑、订阅发布及宿主机独立 Grok 任务是不同模块；看见一个 shadow 标签不能认定整个系统不写配置，也不能认定全部业务已经自动切换。

具体是否开启自动优化、是否被手动接管，以相应业务状态及新鲜度为准。选择唯一自定义节点的业务仍应遵守失效断流，不能为了探测或提高评分自动回落公共出口。

## 8. 订阅管理页（3103）公共来源区

### 8.1 首页卡片与表格

| 项目 | 当前实现的含义 |
|---|---|
| 模式 | 控制器发布模式；不同于 3102 评估器模式 |
| 状态 | 控制器最近一轮状态及是否保留旧来源；不能单凭页面绿色文字判定全部正常 |
| 最新节点 | 本轮候选/发布流程中的 `node_count`；不保证等于原始来源总条目或内核实时数量 |
| 风险分 | 本轮发布门禁计算值；0 分不等于零故障、零风险或全部端点已检测 |
| 来源 / 节点 | 来源标识及最近记录的规范化数量；可能受到保留旧版本逻辑影响 |
| 最近成功 | 来源记录的最近成功时刻；不保证该轮所有新端点已发布 |
| 最近错误 | 抓取、准入、保留旧发布等受控原因，不能只看是否有节点 |
| 发布历史 | 版本、状态、节点数、风险及原因；用来核对哪轮进入生产 |

页面没有完整原始订阅编辑器。公共来源由实际控制目录的 `subscription-sources.json` 管理；不要将 3103 下方“本地自建订阅”的替换模式误解成修改所有供应商来源。

新增“订阅用量（自动识别来源）”区域，按清单中的启用公共来源独立显示套餐与获取状态，约每 30 秒刷新；它与本轮节点候选数、发布状态和本地自建节点是不同数据。用量卡片正常不证明新节点准入已经通过，详见[自动显示说明](subscription-usage-auto-20261027.md)。

### 8.2 发布状态

| 状态 | 含义与下一步 |
|---|---|
| `published` | 本轮发布流程完成；仍需看运行有效数、观察期及真实业务 |
| `unchanged` | 候选与当前发布内容一致，不等于上游没变化、没有待测新节点或系统无告警 |
| `held` | 门禁、缓存依赖、确认不足或资源/控制权忙导致暂缓，先看原因 |
| `rejected` | 未通过硬门槛，不把候选直接推到生产 |
| `rolled_back` | 发布验证或观察失败后退回；核对前一发布是否继续服务 |
| `shadow` | 观察候选，未据此替换当前发布 |
| `degraded` | 控制器层面存在问题，可能仍在服务最后一个可用发布 |
| `awaiting_sources` | 没有启用来源，管理服务可能正常，但代理能力尚未建立 |

`degraded` 是控制器健康层状态，可能与 `release_status=unchanged` 同时出现。`/health` HTTP 200 也可能表示“有旧发布可继续服务的降级状态”，不能只监控状态码而忽略正文和结果年龄。

### 8.3 节点数少时的核对顺序

1. 记录来源、时间、最后错误和发布版本，确认没有只看某个国家筛选或业务池。
2. 去掉套餐说明项、无效条目及重复端点，区分同名与同端点。
3. 核对新端点是否通过准入；`busy` 是检测器忙，不能等同节点已失败。
4. 核对该来源是否保留旧发布，不能用新上游数直接和旧发布相减。
5. 对照当前 manifest、provider API 的有效节点和策略菜单，最后才判断显示缺失还是实际未加载。

本轮发现的孤儿检测进程持锁和 busy 长缓存尚未修复，不通过取消准入、删除锁文件或强推节点来凑数量。[问题记录](diagnostics-20261027.md)列出实际样本及后续方案。

## 9. 3103 下方“本地自建订阅”编辑器

### 9.1 解锁与添加

1. 使用独立管理密钥点击“解锁管理”。本环境密钥文件是 `/root/dpanel/compose/lan-center/data/failover/subscription-controller/local-source/admin-token`，只在自己的受信 SSH 终端读取。
2. 默认选择“追加节点（自动去重）”，每行粘贴一条完整分享链接。
3. 点击“解析并校验”，检查去重后的数量、协议和脱敏备注。此时尚未保存或发布。
4. 点击“保存并发布”，等待页面分别显示保存结果和“旁路由已读取并核验”。
5. 健康检测自动排队；在 3102 查看后续结果，再到 OpenClash 的 `🔐 自定义节点` 选择实际节点。
6. 仅让需要固定出口的业务选择该全局入口，然后做真实业务验收。

支持 SS、VMess、VLESS、Trojan、Hysteria2、SOCKS5、HTTP(S) 的已实现参数子集。一次最多 100 个节点、约 192 KiB 节点文本；不调用公网转换站。未知关键参数会拒绝，不能以删除参数的方式假装兼容。详见[本地订阅使用与恢复](../monitoring/lan-center/local-subscription/README.zh-CN.md)。

### 9.2 按钮、编辑与删除

| 操作 | 行为及影响 |
|---|---|
| 追加节点（自动去重） | 合并现有自建数据；公共来源独立保留 |
| 替换全部自建节点 | 仅替换自建来源，可能移除正在用的自建出口；有确认提示 |
| 编辑 | 选择行后粘贴一条新的完整链接；界面不返回原密码或原始分享链接 |
| 删除 | 移除该自建节点；若正被选中，自定义入口先阻断 |
| 取消编辑 | 放弃当前编辑状态，不恢复已经发布的历史版本 |
| 刷新状态 | 重新读取保存/加载/评估状态，不强制新建一轮全节点检测 |
| 退出管理 | 退出编辑会话，不停用已发布节点或改变业务选择 |

编辑、替换或删除当前选中的自建节点时，系统可将全局入口切到 REJECT，并关闭经过该入口的相关连接，以避免继续使用旧出口。所有引用该入口的业务都会受影响；不能承诺这类写操作完全不中断。

### 9.3 常见错误

| 提示 | 处理 |
|---|---|
| 管理密钥不正确 / 登录过期 | 核对凭据类型，重新解锁；不要重置整个服务 |
| 登录尝试过于频繁 | 按提示等待，不连续提交 |
| 数据已更新，请刷新状态 | 其他操作改变版本；重新读取后审阅再提交，不能强推旧版本 |
| 另一个发布任务正在进行 | 等待并核对任务状态，不删除 writer.lock 或 pending 文件 |
| 上次发布正在恢复 | 先等待或审阅恢复结果，禁止覆盖未完成事务 |
| 当前内核不接受配置 | 保留原配置，核对协议和参数；不通过关闭原生校验解决 |
| 发布失败，保留上一版本 | 先刷新检查实际保存/运行状态，再按对应版本恢复；不要重复点击替换 |

界面成功应拆成“已保存”“内核已加载”“检测通过”“真实业务可用”四层记录。订阅更新不会重建独立自建数据，但误删卷、整机旧快照恢复及错误手工导入仍可能丢失数据。

## 10. DPanel、Docker 与 CoreDNS

当前在 249 的容器列表中查找 `clash-center`。Kuma、CoreDNS、订阅管理和节点能力评估是容器内的服务，不会各显示为一个独立容器；过去的 `clash-kuma` / `clash-failover` 名称和双容器操作手册仅供历史追溯。

| 需要查看 | 如何判断 |
|---|---|
| 三个页面是否发布 | 核对实际容器端口映射 3101/3102/3103，不靠镜像默认端口猜测 |
| DNS 是否发布 | 本环境为 53/TCP+UDP；其他局域网向导默认不发布 DNS |
| 容器是否健康 | 看状态及具体服务结果；healthy 不代替 DNS 查询、写入持久化和真实业务验收 |
| 数据是否持久化 | 核对实际 `/data`、Kuma 数据及配置挂载；新建容器不等于原数据仍在 |
| 为什么不显示“CoreDNS failover”容器 | 它不是当前架构里的独立容器名；DNS 上游/回退需要核对实际 Corefile 和运行结果 |

不要为刷新某个页面重启整个 `clash-center`：中心 DNS、监控、评估及订阅服务会一起受到影响。`docker compose down -v`、删除卷、改挂载目录不是排障步骤。

CoreDNS 没有在这里新增一个独立管理网页。DNS 查询成功只覆盖该请求；代理出口的 IPv6、终端 DoH/DoT 和局域网 DHCP 是不同层次，不能相互替代验收。

## 11. 只读检查与故障证据

以下示例在 249 的受信 SSH 终端执行，不更改配置。端口变化时按实际站点调整；HTTP 503 的正文同样需要保留和分析。

```sh
# 分别读取服务健康；不能仅凭一个 200 判定全部业务健康
curl -sS --max-time 8 -w '\nHTTP=%{http_code}\n' http://10.88.0.249:3102/health
curl -sS --max-time 8 -w '\nHTTP=%{http_code}\n' http://10.88.0.249:3103/health

# 只输出容器状态、健康与重启次数，不导出含凭据的完整 inspect
sudo docker inspect --format '{{.State.Status}} {{if .State.Health}}{{.State.Health.Status}}{{end}} restart={{.RestartCount}}' clash-center

# 候选数据库任务仅收集校验，不代表已替换生产库
sudo systemctl status clash-geodata-trial.timer --no-pager
sudo cat /root/dpanel/compose/lan-center/data/failover/geodata-trial/state/status.json
```

排障记录至少包含：北京时间、设备/网络、域名或业务、预期出口、实际表现、具体子监控/发布状态、规则和完整连接链、结果年龄、对应版本。公开分享时删除密钥、完整订阅 URL、节点原始配置及个人账号信息。

| 现象 | 先排查 |
|---|---|
| 所有页面打不开 | 到 249 的局域网连接、容器状态及端口映射 |
| 页面可开但数据停住 | 结果时间、后台进程、依赖 API 和调度，不把旧数据当最新成功 |
| 单个业务慢 | 真实域名及连接链、首字节/失败率、节点能力、账号/站点限制 |
| 全网慢 | 爱快线路/带宽、249 CPU/内存/磁盘、DNS；不能只换一个节点得出全网原因 |
| 节点数不符 | 来源条目、过滤、去重、准入、保留旧发布和内核有效数 |
| 无订阅信息 | 获取地址及响应元数据，不修改正常的节点发布地址 |
| IP 显示 IPv6 | 检测目标、请求路径、代理出口与终端 IPv6 分开检查 |
| DNS 53 可达但查询失败 | 分别测 UDP/TCP、RCODE/答案及上游；端口可达不足以验收解析 |

## 12. 备份、回退与验收要求

变更前保存实际文件与散列、业务选择、发布指针、运行 provider 数、配置和相关数据库在线备份，并确认设备身份及回退入口。Kuma SQLite 的活动文件不能当普通静态文件直接复制后就宣称备份完成。

本环境接管及分流维护有不同事务和备份，不能相互覆盖：

| 类型 | 应查文档 |
|---|---|
| 0.1.1 中心接管 | [生产部署记录](production-deployment-20261026.md) |
| 75 个稳定自动入口、系统总裁直连与候选四库 | [分流维护记录及专用恢复命令](routing-maintenance-20261027.md) |
| 安装途中断线及常规 restore | [安装器恢复手册](../installer/RECOVERY.zh-CN.md) |
| 自建节点发布或数据恢复 | [本地订阅恢复说明](../monitoring/lan-center/local-subscription/README.zh-CN.md) |

恢复命令是生产写操作，只用于对应事务；遇到新人工改动或身份不符应停下来核对，不能绕过检查。没有为本轮文档更新创建新的生产备份或部署事务。

验收分为配置正确、服务健康、实际规则命中、真实业务和持续观察。页面正常、CI 通过、原生 `-t` 通过和单次 HTTP 200 各自只覆盖一部分；未完成的阶段明确写待验收。候选数据库仍未切生产，既有准入问题未在此次修复；两个来源套餐信息已按自动显示事务完成，见[问题清单](diagnostics-20261027.md)。
