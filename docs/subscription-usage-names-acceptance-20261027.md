# 机场名称与 N 来源严格验收 · 2026-10-27

用户要求按不固定数量自动适配，而不是只验证第三个来源。本轮沿用节点发布、DNS 和业务选择，扩大了来源生命周期验证，并修正机场显示名。

## 名称问题与修正

当前两个来源配置中的 `name` 是通用标签 `source-1/source-2`。原始订阅实际返回的 `Content-Disposition` 带 RFC 5987 编码文件名；采集器此前只解析套餐用量，因此没有显示供应商返回的名称。现在 3103 用量区和 OpenClash 配置卡片均显示“良心云”“🐮牛逼”，实际页面核验一致。

通用命名优先级如下：

1. 清单显式 `display_name`，或现有非通用的自定义 `name`；尊重手工别名，不覆盖用户命名。
2. 原始订阅最终 HTTP 响应的 `profile-title`，支持普通文本、`base64:` 与 MIME 编码。
3. 最终响应 `Content-Disposition` 的普通文件名或 RFC 5987 编码文件名，去掉常见配置扩展名。
4. 未返回可靠名称时显示“未识别机场 · 原来源标签”。不把域名、节点名、`clash.yaml` 等通用文件名猜成机场名称。

名称只用于显示，不重命名 provider ID、节点、策略组或规则引用。转发账号、原始 URL、发布 Token 和私钥不进入名称；不合法编码不会阻断有效用量。只有名称、没有套餐头时仍能显示名称，但用量保持“未获取”。

识别名称随账户身份缓存；失败时保留已识别名称。相同来源 ID 改订阅 URL 时清除旧账户自动缓存的名称与用量；显式手工别名仍由用户维护。成功的旧格式缓存升级后补查名称，既有限流/失败的退避时间保持有效，不因升级强行重试。供应商自己提供错误标题仍需要手工别名覆盖，不能称为外部名称核实服务。

## N 个来源与 N 个节点

- 来源数量取自当前清单，可新增、删除、停用和重排，不使用第一个、第二个、第三个的固定位置映射。
- 当前清单总条目保护上限为 128，含停用项；超限时明确报错并保留最后有效清单，不丢弃尾部来源或覆盖有效状态。
- 每个来源对应自己的套餐，不把一个来源中的节点数量当作多个套餐。用量模块只读取信息头，不枚举节点正文；节点发布器原有资源与准入限制不变，不能据此宣称任意数量节点都可发布。
- 请求并发及待处理队列始终不超过 2。调度按到期时间排序，使新来源及从未检测过的来源先于失败重试，避免早期来源反复重试挤占后续来源。
