# 系统使用与维护手册

环境地址和版本以[生产部署记录](production-deployment-20261026.md)为准。新局域网必须重新填写地址、网段、SSH 指纹和端口。

本文是日常操作总览。[管理页面完整操作手册](management-pages.zh-CN.md)逐项介绍 OpenClash 首页、Metacubexd/Zashboard、Kuma、3102、3103、DPanel，以及按钮影响、状态字段、操作流程和只读检查。[当前问题记录](diagnostics-20261027.md)区分已验证结果与尚未修复项；两个订阅来源用量已由[自动显示事务](subscription-usage-auto-20261027.md)恢复，后续增删自动同步。既有准入问题不属于本次用量维护范围，不能只凭文档已同步判断全部问题完成。

## 1. 页面与权限

| 本环境入口 | 用途 | 权限 |
|---|---|---|
| `http://10.88.0.249:3101/` | Kuma 历史与告警 | 原 Kuma 账号；组故障先展开子项 |
| `http://10.88.0.249:3102/` | 节点能力、业务探测、结果新鲜度 | 评估器 shadow，不自动接管全部业务 |
| `http://10.88.0.249:3103/` | 公共订阅状态与本地自建订阅 | 编辑需独立凭据；页面可达不等于有写权限 |
| `http://10.88.0.254/` | OpenClash / LuCI | 配置、日志和策略面板 |

只读页面供受信局域网使用。局域网可达不等于传输已加密；公网访问需另配认证与加密，不直接映射控制 API 或编辑端口。

当前 `clash-center` 是一个容器内运行多个服务，Kuma/CoreDNS 不会在 DPanel 中各显示一个容器；重启中心会同时影响这些服务。查看[页面与容器对应关系](management-pages.zh-CN.md)后再执行维护，不使用历史双容器命令。

## 2. 选择业务出口

找到具体业务组，再选该组现有菜单项。各组菜单以实际 API 为准，不保证完全相同。

本环境后续维护已为 69 个业务组和 6 个指定功能选择组补齐 `🛟 稳定自动`，不改原默认项或当前选择；自定义入口、专用池及技术自动池不批量加入其他出口。持久覆写位置、系统总裁直连和本轮恢复命令见[分流维护记录](routing-maintenance-20261027.md)。

| 入口 | 行为 |
|---|---|
| 默认策略 / 功能父组 | 继承上级选择 |
| DIRECT | 直连 |
| REJECT | 阻断命中的连接 |
| 稳定自动 / 自动选择 | 按对应组的实际类型、成员和探测策略工作 |
| 手动选择 / 国家地区组 | 继续在该组选择；名称不证明真实出口国家 |
| 业务专用池 | 使用本业务成员和控制机制；通用测速不等于业务验收 |
| `🔐 自定义节点` | 全局唯一，直接选择实际节点；所有引用它的业务共用选择 |

自定义入口保留 REJECT 为默认项，可列出有效订阅节点及自建节点。选定节点故障时断流，不跳到 DIRECT 或其他节点；节点从源中消失后的空态应回到 REJECT。改选会影响所有引用该入口的业务。

锁定只作用于实际命中对应规则的连接。Google、Gemini、YouTube 分组独立；共享资源可能先命中其他规则，详见[专属出口说明](strict-custom-egress.md)。验收改选时应新建请求，不要批量中断其他业务长连接。

## 3. 在 3103 添加自建节点

1. 打开“本地自建订阅”，使用编辑凭据登录。
2. 粘贴链接，先预览解析与 Mihomo 原生校验结果，核对数量、类型和脱敏名称。
3. 确认后发布，等待运行加载结果；随后到 OpenClash 的 `🔐 自定义节点` 查看。
4. 需要固定出口的业务选择这个入口，再做真实登录、对话等验收。

解析器支持 SS、VMess、VLESS、Trojan、Hysteria2、SOCKS5、HTTP(S) 的已实现参数子集，不保证任意扩展或全部协议。未知关键参数应报错，不能靠静默删参数通过校验。

发布使用认证、同源/CSRF、版本冲突检查、节点校验及 provider 运行检查。失败时先查看受控原因、重新读取版本，避免连续强推。编辑凭据、provider 凭据和 OpenClash API 密钥不同。

| 数据 | 全新安装 | 本环境接管 |
|---|---|---|
| 控制数据 | `/opt/clash-stack/<站点>/data/control/` | `/root/dpanel/compose/lan-center/data/failover/` |
| 自建数据及凭据目录 | 控制目录下 `subscription-controller/local-source/` | 同左 |
| Kuma 数据 | `/opt/clash-stack/<站点>/data/kuma/` | `/root/dpanel/compose/lan-center/data/uptime-kuma/` |

编辑凭据文件为 `admin-token`，provider 凭据文件为 `provider-token`。仅在受信终端查看实际值，不写 Git、URL、截图或工单。公共订阅更新不覆盖自建数据；误删挂载目录、整机回退和错误手工导入仍可能丢数据，必须备份。

## 4. 公共订阅与能力数据库

公共来源位于控制目录的 `subscription-sources.json`。系统依据配置识别 0、1、2 或多来源，不依赖固定机场名称。3103 自建编辑与公共来源配置是不同入口，不承诺网页可修改所有公共源设置。

**名称、用量已改为独立信息清单。** 249 定时只读读取 OpenClash“编辑配置文件订阅信息”中名称精确为“转换”的条目，自动增删信息来源；保留人工信息条目。独立清单位于控制目录的 `subscription-usage/information-sources.json`，不会写上面的节点发布清单。当前“转换”的 3 个地址会进入信息显示，而节点发布清单仍是原 2 家；信息卡片增加不代表新增节点已发布。详见[单向同步、恢复与限制](subscription-info-sync-20261027.md)。

安装向导隐藏输入来源地址。已有生产来源变更先备份和校验，不手改发布指针，不把未经准入的上游内容覆盖当前发布。抓取失败、异常降幅或准入失败时保留旧版本；有缓存不代表本轮实时更新成功。

3103 的来源数量、候选 `node_count`、当前发布及内核运行数是不同口径；“未变化”也可能伴随保留旧来源的 degraded。当前已发现隔离测试进程持锁及 busy 长冷却，仍待修复，不能把所有未准入节点认定为失效，详见[节点数量取证](diagnostics-20261027.md)。

OpenClash 配置卡片的“无订阅信息”指套餐元数据没有取得，不能用内核运行流量冒充套餐用量。249 按独立信息清单分别取数、缓存、退避，在 3103 与 OpenClash 卡片显示，节点拉取仍经原地址。地址同步约 30 秒、用量正常采集约 600 秒，页面约 30 秒刷新；来源越多或有限流时越慢。新增、停用、删除无需逐条再绑 OpenClash。失败无历史时显示未获取，有历史时标缓存及时间。空到期只表示未提供，不表示永久有效。历史实现见[自动显示](subscription-usage-auto-20261027.md)，最新部署与恢复以[单向同步记录](subscription-info-sync-20261027.md)为准。

后续已补充[机场名称与 N 来源验收](subscription-usage-names-acceptance-20261027.md)：中文和编码标题自动识别，手工显示名优先，改账户不继承旧名称。保护上限内按实际来源清单增删重排，不将节点数量等同于套餐数量；同页有最新增量备份和恢复命令。

### 4.1 订阅更新及重启后的恢复

[17 项隔离恢复验收](subscription-restore-acceptance-20261027.md)已覆盖订阅原地址内容更新、进程重启、实际容器重启、保留数据卷删除重建及 128 个来源热缓存读取。被测对象是订阅元数据组件，生产中心没有重启。

自动恢复需要保留完整控制数据、来源清单、元数据认证及当前启动代码映射，不能只留一个用量缓存文件。当前站点容器内 `/data` 对应本手册的控制目录；其他站点先核对自己的实际挂载。

| 条件 | 恢复时怎样理解 |
|---|---|
| 清单、缓存、认证及挂载完整 | 名称、历史用量和所有来源可恢复，无须重新绑定元数据认证；新值随后按计划取数 |
| 上游暂不可用但缓存仍在 | 先显示历史成功值；核对最后成功时间，不能把重启当成一次成功联网 |
| 缓存损坏、上游可用 | 可重新获取；上游须实际提供名称和套餐字段 |
| 缓存损坏且上游离线 | 清单可保留，名称/用量未获取；上游恢复后按退避计划补齐 |
| 来源配置或整个数据卷丢失 | 先核对挂载及可信备份，不能把自动生成的空配置当成恢复完成 |

检查时先看来源数、状态和时间，不用切换业务组、更新节点文件或重启 DNS 来刷新套餐。生产约 600 秒取用量、页面约 30 秒刷新；隔离更新场景的 3 秒周期不是生产承诺。17 项结果、持久路径、代码回退与数据恢复的区别、尚未验证范围见[完整记录](subscription-restore-acceptance-20261027.md)。

### 4.2 能力数据库与分流数据库

能力数据库为控制目录的 `node-capability.db`；健康状态为 `node-capability.health`，订阅状态为 `subscription-controller/health.json`。这是持续检测得到的本地历史，不是第三方“全球业务可用节点数据库”。未评估、结果过期和业务受限应分别判断。

域名/IP 分流数据库与上述节点能力数据库不同。原 OpenClash 四库每日自动更新保留；新增 MetaCubeX 候选每 6 小时收集校验，只写 `geodata-trial/state/`，尚未替换生产库。`candidate_ready` 表示数据校验和当前内核兼容检查通过，不代表全量域名分流与业务验收完成，详见[候选任务及停止方法](routing-maintenance-20261027.md)。

检测器使用隔离组和认证入站，区分通用联网与具体业务，并记录 DNS、TLS、超时、限流、地区及风控等结果。低延迟不等于联网或业务可用；403/429 需按目标语义判断。频率以实际运行环境变量为准，历史默认值不代表当前值。

能力评估 shadow 与 ChatGPT 等既有控制器分工不同，不能据此认为全部模块只读。独立 Grok 切换任务运行在宿主机，接管保留，不自动搬进容器。

## 5. DNS 与接入边界

接管保留现有 CoreDNS 上游、监听和访问范围；安装器不改爱快 DHCP、下一跳、DoT 防火墙、Windows DNS 或系统代理。新站点默认不发布 DNS，启用前必须验证上游及 UDP/TCP 查询。

应用自带 DoH、DoT、VPN、IPv6 或外部代理可能形成独立路径。中心 DNS 正常不等于全网无泄漏，也不证明每台设备使用它。旁路由接管流量不等于所有解析一定经过指定 DNS。

首页 IP 检测展示对应检测站看到的出口：本地 IPv4 经代理后可以使用代理服务器的 IPv6。取证已复现这种情况；它不代表给局域网开启了 IPv6，也不足以单独证明全网无泄漏。详见[IPv6 取证与解释](diagnostics-20261027.md)。

## 6. 备份与恢复

在完整离线包目录执行。Windows 前缀 `./start.ps1`，Linux 前缀 `sh install.sh`：

```text
doctor --profile sites/home.json
plan --profile sites/home.json --output sites/home.plan.json
backup --profile sites/home.json
install --profile sites/home.json --plan sites/home.plan.json
verify --profile sites/home.json
restore --profile sites/home.json
```

doctor、plan 只读，计划有效 30 分钟。接管使用原站点档案，不改站点名绕开状态校验。备份实际路径看收据；本环境本轮专用救援脚本及独立基线见[部署记录](production-deployment-20261026.md)。

常规 restore 回退程序/配置并保留运行数据，不自动覆盖新数据库记录。数据库损坏需另外审阅备份恢复。完整步骤及断线保护见[恢复手册](../installer/RECOVERY.zh-CN.md)。

## 7. 排障顺序

| 现象 | 先看证据 | 原则 |
|---|---|---|
| 全网慢 | 爱快带宽/线路、249 存储延迟、容器负载、DNS 时延 | 不直接重启全部服务 |
| 单业务失败 | 时间、域名、错误内容、实际 connections 的完整 chains | 先核对规则和风控，再改专用出口 |
| 延迟正常但打不开 | 通用与业务结果、TLS、响应内容、结果年龄 | 延迟不是可用性证明 |
| 订阅没有新节点 | 抓取时间、准入原因、当前发布、运行 provider 数量 | 缓存不能冒充实时成功 |
| 自建节点没出现 | 发布状态、原生校验、Local_Custom 运行加载 | 占位 REJECT 不是真实节点 |
| Kuma 反复故障 | 具体子项、探测目标、重试、超时 | 主页成功不代表 API 或账号可用 |
| 安装验收失败 | 双端 transaction/state、受限日志、恢复记录 | 不删事务或绕过保护继续覆盖 |

仅导出必要状态。完整 docker inspect、Compose、订阅 JSON 和日志可能包含密钥，不应公开。

## 8. 验收要求

至少核对设备身份、配置/规则/业务选择、镜像与代码散列、三个页面、DNS UDP/TCP、国内/海外/关键业务请求、provider 与凭据、Kuma 逻辑数据和完整性、其他容器的部署窗口状态、回退材料。

账号登录、发送消息、播放、蜂窝外网回连需要相应设备与账号确认。短时成功与长期稳定分别记录；单机及外部互联网依赖不能保证永久免维护。
