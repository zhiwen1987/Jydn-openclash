# 全系统一键部署安装包规划

日期：2026-10-26。**本文件是方案，不是已交付的安装包；本轮不额外部署安装器。**

建议采用一个安装器、两种部署方式：已有局域网使用「接入现有环境」，新局域网使用「全新部署」。两者复用同一套版本、参数、验收和恢复引擎。正常生产仍集中在一个 `clash-center` 容器，旁路由保留上游 OpenClash 与适配的 Mihomo 内核。

## 安装包包含什么

| 部分 | 交付内容 | 持久数据 |
|---|---|---|
| 旁路由 | 配置编译器、业务目录、规则、订阅关联、独立回退守护 | 用户规则、选择状态、专属出口绑定、provider 缓存 |
| clash-center | 订阅管理、节点能力评估、路由质量控制、Kuma、CoreDNS、进程监督 | 订阅与自建节点、SQLite、监控配置、状态与证据 |
| 安装器 | 预检查、差异计划、备份、分步安装、验收、升级与恢复 | 环境档案、事务日志、备份索引 |
| 离线资源 | 固定摘要的镜像、适配版本的程序与规则、校验文件 | 版本清单与来源记录 |
| 中文手册 | 初装、迁移、日常操作、断网恢复、主路由接入步骤 | 不含账号密码或 Token 的示例 |

SSH 密码、订阅 Token、节点凭据和私钥不会放入安装包或 Git。它们在目标环境单独输入、生成与保存，备份加密时由用户持有恢复口令。

## 必须先识别环境

一次向导收集 Docker 主机、旁路由、主路由、网段、监听端口、订阅来源、DNS 接管意图和管理凭据。自动检测结果与用户输入一起生成可复用的环境档案。

预检查至少包括：

- OpenWrt/iStoreOS、CPU 架构、OpenClash/Mihomo 版本与功能支持；内核必须真正支持所用 provider、过滤与阻断行为。
- Docker/Compose、目录权限、磁盘余量、数据库写入、监听端口冲突、服务现有挂载和实际执行用户。
- SSH 主机指纹、旁路由 MAC/IP、重复 IP、管理连接的实际路径；避免连接到同 IP 的另一台设备。
- 当前路由、DNS、DHCP、IPv6、网关和主路由下一跳，时间与证书条件；发现异常先给出证据，不自动改 Windows 时间、网关或代理。
- 订阅有 0、1、2 或更多来源时分别识别；来源标识稳定，不能依赖名称、顺序或固定的“两家机场”假设。

不能确认兼容性时停止安装，并保留现状。第一版支持范围应先限于本次有实机证据的架构与系统组合；其他平台在完成隔离验收后再加入兼容表。

## 实际安装顺序

1. **只读体检与差异预览。** 列明将创建、修改和重启的具体对象，标出已有业务冲突。
2. **建立恢复通道。** 在线一致性备份 SQLite，保存原配置、原镜像摘要、选择状态和私有绑定；在宿主机与旁路由各准备一个独立于中心容器的恢复守护。
3. **隔离验证。** 使用独立数据目录和端口校验配置、协议解析、数据库迁移、依赖与恢复过程，不挂载生产数据库做实验。
4. **部署中心服务与旁路由配置。** 幂等安装，只管理明确归属安装器的文件；保留其他程序、容器和自定义内容。已有环境优先更新所需子进程，涉及容器重建时单独列明 DNS/Kuma 停顿风险。
5. **单设备或单业务灰度。** 先验证订阅、规则命中、实际出口、DNS 与故障行为，再扩大流量范围。自定义出口保持用户选择，故障阻断，不擅自回落。
6. **完成验收并解除保护。** 真实读取运行状态和业务结果，保存通过项、未验项及恢复入口。管理链路断开、超时或指标恶化时执行对应阶段的有界回退。

安装过程应可中断后继续；重复运行不产生重复组、重复定时任务、重复容器或新的默认出口。

## 安装器操作界面

建议交付 Linux 命令行与 Windows 启动器。Windows 端仅用来连接远程设备和显示安装进度，不修改 Windows 程序、系统代理、DNS 或其他业务应用。

下面是**拟议操作名称，目前并非已有命令**：

| 操作 | 作用 |
|---|---|
| 体检 / doctor | 输出兼容性、网络路径、资源与运行状态 |
| 预览 / plan | 展示将发生的变更与风险 |
| 安装 / install | 按已确认档案分步实施 |
| 验收 / verify | 结构、运行与业务验证，并标明证据边界 |
| 备份 / backup | 保存配置、状态、数据库和恢复索引 |
| 恢复 / restore | 从明确的备份恢复，拒绝覆盖未知的新改动 |
| 升级 / upgrade | 使用固定版本，先预演，再按兼容性升级 |
| 移除 / uninstall | 移除安装器拥有的对象，业务数据默认保留 |

## 自动化要做到哪些事

来源独立发布、去重、协议校验、订阅更新防覆盖、最后正常版本、空源阻断、节点增删发现和健康结果入库应自动完成。繁忙任务进入有界队列，版本冲突不能自动覆盖用户更新。

健康评估沿用一个调度器与一个数据库，探测并发有上限，优先处理新节点与故障复核，正常节点降低探测频率。延迟、实际访问、业务限制和结果时效分别记录，不能把单次测速或一个 HTTP 403/429 等同于业务可用／节点故障。

支付、交易和用户明确锁定的出口，不因“更快”而自动更换。自动控制器遵守业务选择和私有绑定；状态损坏时保持可解释的阻断或最后正常状态，不猜测其他出口。

日志、探测历史、版本、备份和镜像应有独立保留策略；任务结束释放临时进程与实验容器。持续记录 CPU、内存、磁盘与探测流量，验收后再给出资源数据，不提前承诺任意硬件的占用数值。

## 一键部署的边界

现有环境已经有可用 SSH、Docker、旁路由和主路由导流时，可以把应用层安装、配置与验收做成一键流程。

全新局域网的光猫、PPPoE、交换机 VLAN、WAN 线序、爱快 DHCP/DNS/下一跳不能仅凭模板推断。爱快自动写入接口须先核实版本和可恢复性；没有可靠接口时，由安装器生成中文参数清单、操作步骤和回读验收，不宣称已经配置成功。

真实账号登录、地区风控、供应商授权，以及必须由用户在外网完成的业务检查，需要明确显示“待用户确认”。其他联网设备及 Windows 配置保持在用户授权范围内。安装成功不等于任何目标网站永不故障，也不能据此承诺 99.999999% 端到端可用率。

## 发布与验收门槛

| 场景 | 必须证明的结果 |
|---|---|
| 初装、重复安装、恢复、升级 | 无重复对象；配置及状态可迁移，失败可恢复 |
| 一源、两源、失效源、节点改名 | 各来源独立；失败不覆盖最后正常内容 |
| 本地节点添加、编辑、删除、空来源 | 可读回，更新不覆盖，失效阻断 |
| 节点延迟正常但不能访问业务 | 被标为相应故障／受限／未知，不能误标全业务健康 |
| DNS 与规则 | 按指定测试集命中；读取实际路径与出口，无新引入的循环 |
| 容器与路由器重启 | 原始数据、凭据、入口、绑定和选择状态可恢复 |
| 中断安装、控制器故障、磁盘满 | 明确停在哪一阶段，保留恢复通道，无无限重试或重启风暴 |
| 真实业务与外网 | 根据实际网络及账号结果记录，不用模拟结果冒充通过 |

镜像和二进制固定摘要，包含来源、校验和、依赖与许可证记录。升级以单一版本清单协调，保留已验证版本；控制器与配置不能同时无保护更新。

## 后续实施拆分

1. **规范与冻结**：整理当前真实文件、依赖、凭据位置、可迁移数据与验收证据，确定环境档案和版本清单。
2. **打包与适配**：制作统一镜像、离线资源、预检查及事务安装器，完成导入导出和备份恢复；主路由对接单独适配。
3. **空白环境预演**：从零安装、再次安装、升级与回滚，验证整机和容器重启，以及断网时独立恢复。
4. **现场灰度与发布**：先复核现场备份和控制台，再灰度安装，完成真实业务验收后发布正式安装包与中文手册。

本轮已完成的 3103 本地订阅功能可作为来源管理模块复用。整套安装器、通用镜像、离线包与上述跨环境验收仍属于后续工作。
