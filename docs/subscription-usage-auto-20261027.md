# 多订阅来源用量自动显示 · 2026-10-27

本次已在 249 的 `clash-center` 和 254 的 OpenClash 配置卡片上线。当前两个公共订阅来源均返回有效用量；不再把其中一家固定为这份配置唯一的信息来源。后续第三家及更多来源按同一清单自动识别。

后续已完成[机场名称识别与 N 来源严格回归](subscription-usage-names-acceptance-20261027.md)：修正 `source-1/source-2` 通用标签，增加独立调用的依赖声明，并补充容量、公平调度、真实 HTTP 生命周期和原生页面缓存检查。该后续事务有新备份，撤销时先按新记录恢复，不能直接用本页旧事务覆盖后来改动。

## 操作方法

1. 打开 `http://10.88.0.249:3103/`，查看“订阅用量（自动识别来源）”。OpenClash 首页当前配置卡片也分别显示各来源的已用、总量、剩余、到期与最后成功时间。
2. 沿用现有公共订阅来源管理流程维护 `subscription-sources.json`。它是现有控制器的清单，扩展名虽为 JSON，也兼容现用 YAML 内容；不是要求把账户地址再填到每个 OpenClash 策略组里。
3. 新增、停用或删除来源后，采集器约每 2 秒检查清单变化，页面每 30 秒刷新。OpenClash 浏览器信息缓存缩短到 15 秒；缓存刚写入或供应商响应慢时，可能再等一轮。首次升级后浏览器执行一次 `Ctrl+F5`，避免沿用旧脚本。
4. 正常来源约每 10 分钟重新取用量；打开页面只读中心缓存，不会每次同时请求所有供应商。计费用量与到期以供应商实际返回为准，不是 OpenClash 的运行流量统计。

这里的“所有来源”指现有清单中启用的公共订阅来源，清单总条目保护上限为 128（包括停用条目）。一个订阅里的几十或几百个代理节点不各自对应一个套餐。本地自建节点没有供应商套餐头，不伪造套餐；本模块也不改变节点发布器已有的数量、资源和准入限制。

## 显示状态

| 状态 | 含义及处理 |
|---|---|
| 正常 | 最近一次取得有效套餐字段，显示最后成功时间 |
| 等待获取 | 新来源尚未完成第一次请求 |
| 缓存 | 最近请求失败或旧结果已超时；保留成功值并标明时间，不冒充实时值 |
| 获取失败 | 没有成功历史，显示“未获取”及受控错误类型，不填零 |
| 来源限流 | HTTP 429，遵守数字型 Retry-After；未提供有效值时退避约 15 分钟 |
| 配置读取失败 | 清单暂时损坏，保留上次识别清单并明确提示，不能把它当作所有来源已删除 |
| 暂无启用来源 | 有效清单为空，正常显示零个来源，不是零流量套餐 |

供应商没有 `subscription-userinfo`、接口返回 403 或账户过期，不能靠本功能生成真实用量。缺失或无效字段保持“未获取”；供应商明确返回 `total=0`、`expire=0` 时，页面分别标成“不限量（来源返回 0）”“长期（来源返回 0）”。

在线转换只在能确定唯一内嵌 HTTP(S) 原始地址时解包；合并多个机场的转换地址不随意合并计费用量。可在现有来源条目里选填 `info_url` 指定该来源的信息接口，这不替换 `url` 节点下载字段。不支持的一体化多账户接口需单独适配，不能保证任意供应商都能自动提供套餐。

## 数据路径及故障隔离

```text
3103 现有来源清单
  → 中心内的独立用量采集任务（最多 2 个并发请求）
  → 各来源的独立结果、缓存和退避时间
  ├→ 3103 /api/subscription-usage → 每家独立卡片
  └→ /subscription-info → OpenClash 元数据适配 → 当前配置卡片
```

- 不新增常驻容器或对外端口，复用 `/data` 持久卷。缓存与代码在 `/data/subscription-usage/`，宿主机对应 `/root/dpanel/compose/lan-center/data/failover/subscription-usage/`。
- 每个源的请求有时限；一个超时不等待整个批次，已成功来源继续显示。最多两个工作任务，不积压无界队列。正常刷新 600 秒，失败指数退避 30～900 秒；限流退避最多 3600 秒。超过 1800 秒的旧用量明确标记过期，仅供参考。
- 改地址但保留同一来源 ID 时，旧账户用量不继承给新账户；来源删除后，即使旧请求稍后返回也不能使它重新出现。
- `/api/subscription-usage` 是面向本局域网的脱敏状态接口，可见套餐数字和名称，不含原始地址、节点凭据或发布 Token。沿用用户允许局域网访问管理信息的边界。
- `/subscription-info` 使用独立 Bearer 凭据及既有客户端白名单。凭据仅存私有文件和路由器专用 UCI 字段，不嵌入公开信息 URL、不写仓库。curl 通过标准输入接收地址和认证，不放在命令行参数中。
- OpenClash 仅保留一条自动聚合绑定 `jydn_subinfo_auto`；来源增删无需每次再改路由器 UCI。此前的单来源绑定 `jydn_subinfo_bffc55` 已迁移清理。
