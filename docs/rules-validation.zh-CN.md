# 校验与恢复范围

## 日常门槛

PR 执行规则仓边界检查、模板构建、静态语义验证，以及空组、菜单和自定义出口配置编译测试。发布器单独验证允许清单、引用闭合及敏感数据拒绝，成功后才提交公开规则仓库。

这些检查不连接生产，不替代真实网站、节点可用性、DNS 或网络访问验收。中心 API、Kuma、节点健康数据库和 Docker 部署测试已归属独立私有项目，不在本仓库伪装成仍受覆盖。

## 本次清理的保护条件

- 保留原规则、模板源输入、生成模板与模块 payload 的 Git blob，避免把换行差异混进提交。
- 保留模板构建工作流的名称、写入生成文件能力和公开规则发布凭据。
- 对清理前后公开导出做逐文件比对，并在合并后确认构建和自动发布真实成功。
- 清理仅针对当前仓库文件，既有设备、容器、DNS、订阅与策略选择不操作。

## 恢复

清理前完整 Git mirror（所有分支、标签及历史）和自动更新设置已另行备份，并验证对象完整性。恢复操作应先核对备份引用/散列，再在独立目录恢复仓库或对清理提交做受审阅的 revert；不要直接对生产执行旧运维脚本，也不要盲目 force push。

完整备份位置和具体收据仅在所有者的私有工作记录中保存，不把系统交接资料重新放回公开规则仓库。原提交记录保留，因此本次不代表历史数据擦除或凭据轮换。
