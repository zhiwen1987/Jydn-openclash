## 可靠方案，仅供批准，未实施

在模板的早期第三方直连及 `google-cn` 之前加入两条精确业务例外：

```ini
ruleset=🔎 谷歌服务（Google）,[]DOMAIN,fonts.googleapis.com
ruleset=🎞️ 海外影音,[]DOMAIN-SUFFIX,iq.com
```

位置需保留现有本地网络和用户批准的安全规则优先级。不要把整个 Google 提前到 Gemini、YouTube 等独立业务之前，也不要把所有自定义 DIRECT 一起上移。

这是模板顺序变化，超出本轮 B 的“只改现有 rules 文件且加载关系不变”授权，所以本 PR 不改模板、不新建规则文件、不部署。若用户批准后另开实现 PR，必须使用同一固定样本集重跑，确认仅期望的业务发生变化。

`google-ip-asn.yaml` 是 IP/ASN 后备集，不适合塞入域名冒充覆盖修复。把 `iq.com` 加入 `mygw.yaml` 既不能越过早期直连，也不会进入要求的影音业务组。

## 本轮允许范围内的规则修复

在现有 `rules/direct.yaml` 增加 `+.hhyunerp.com`，覆盖根域和全部子域，恢复用户此前明确指定的永久直连意图。DIRECT 提供器条数由249变为250；没有新增规则文件，没有修改模板、加载关系或其他域名。

A 固定快照中，`hhyunerp.com` 与 `www.hhyunerp.com` 不属于前置 GeoSite 和第三方域名规则，域名阶段原先落入兜底组；补丁使二者明确命中 DIRECT。不以这两条样本的改善宣称两个模板顺序问题已修复。

目标变化仅 `hhyunerp.com` 与 `www.hhyunerp.com` 两条，均为兜底组到 DIRECT；其余2565条目标不变。完整对照见 [`routing-rule-fix-comparison-20261028.json`](../reports/routing-rule-fix-comparison-20261028.json)。样本与模拟器归属 [A 的独立 PR #26](https://github.com/zhiwen1987/Jydn-openclash/pull/26)，不在本 PR 复制工具或快照。对照证据记录了实际使用的模拟器提交和 LF 字节哈希；生成器另有 Windows/Linux 换行一致性回归测试。

上述百分比是固定公共分类政策与规则顺序的**离线一致率**，不是独立人工逐站验证的分流正确率，更不是现网准确率或网络可用率。303条政策待确认样本不进入2264条严格计分分母。未建模目标为0也只限明确声明的域名阶段；IP、端口、进程和复合条件未被纳入该指标。

其中，`.cn` 广告域名与广告优先拒绝、以及通用业务与更具体子业务之间的重叠，作为政策待确认项处理。没有把 REJECT 说成实际走代理，也没有把所有业务目标差异当成可自动修复的故障。完整错配及分类归属 A 的审计报告，剩余312条目标差异未在本 PR 擅自处理。

风险：上游浮动规则未来若新增更早的同域名匹配，仍可能抢先；离线域名模拟不能证明当前生产配置、节点、DNS 和网络可用性。本轮没有连接设备，也没有部署。
