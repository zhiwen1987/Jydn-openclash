# 精准稳定 R4-HA 生产验收与回滚

## 一、离线门禁

以下项目必须全部通过，任一失败均不得上传旁路由：

1. 两次连续生成结果一致。
2. 配置校验无缺组、空引用、循环引用、自引用、错误默认项或规则顺序错误。
3. 99 个组完整存在，其中 19 个为自动池。
4. 四个专用池分别使用规定的业务地址、900 秒间隔与 `100 ms` 容差。
5. 四个专用池包含 `🛟 稳定自动`，不包含 `DIRECT`，并过滤订阅提示伪节点。
6. ChatGPT、Claude、Gemini、Netflix 的默认第一项为各自专用池。
7. 运行期空组过滤测试通过。

## 二、动旁路由前的强制动作

开始本阶段前必须先明确通知用户。不得直接覆盖现网文件。

1. 记录活动配置路径、OpenClash 插件版本、Mihomo 内核版本和当前策略选择。
2. 在路由器生成带时间戳的备份目录，至少包含：
   - 活动订阅 YAML；
   - OpenClash UCI 配置；
   - 覆写模块和自定义脚本；
   - 策略选择状态；
   - 当前 OpenClash 日志及核心版本信息。
3. 下载一份备份到本地项目外的安全位置，并计算校验值。
4. 上传为独立候选文件 `精准稳定-v1-r4-ha.yaml`，不得覆盖 `精准稳定-v1-r3.yaml`。

## 三、沙箱门禁

1. 使用路由器当前 Mihomo 内核对候选 YAML 执行配置测试。
2. 检查 99 个组、19 个自动池、四个业务专用池以及所有规则引用。
3. 逐节点或分批验证四个探测地址，记录可用节点数、失败原因和耗时。
4. 检查 DNS、TLS、HTTP、TCP、UDP、Firewall4 和旁路由回程。
5. 候选文件通过测试后仍不自动切换，等待用户确认生产窗口。

## 四、灰度切换

1. 预置自动回滚任务；若在规定时间内没有人工确认，恢复 R3 并重启 OpenClash。
2. 将活动配置切换到 R4-HA，只重启 OpenClash，不改爱快。
3. 先验证国内直连、`.cn`、AMD 中国、涂鸦智能和五个指定直连域名。
4. 再验证 ChatGPT、Claude、Gemini、Netflix，每项连续成功三次。
5. 验证 DNS 无泄漏、支付/交易组未自动漂移、两条订阅节点都存在、LuCI 日志无新增严重错误。
6. 观察期内确认策略选择恢复正确后，才由用户决定取消自动回滚。

## 五、立即回滚条件

出现以下任一情况立即恢复 R3：

- OpenClash 无法启动或核心配置测试失败；
- 国内站点、智能家居或局域网访问异常；
- DNS 解析间歇性失败或出现明显泄漏；
- 四个关键业务中任一项连续失败；
- 策略组为空、循环、选择丢失或节点数异常；
- 旁路由管理连接不稳定，无法完成验收。

## 六、恢复原则

恢复时将 OpenClash 的活动配置路径指回备份的 `精准稳定-v1-r3.yaml`，恢复对应 UCI、覆写脚本和选择状态，再重启 OpenClash。恢复后必须重新验证国内直连、DNS、AMD 中国、涂鸦智能、ChatGPT、Gemini 和 Google 204；不能只以“进程已启动”作为恢复成功。
