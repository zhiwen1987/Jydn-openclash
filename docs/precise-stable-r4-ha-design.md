# 精准稳定 R4-HA 设计说明

## 状态与目标

- 状态：离线候选，未部署生产，未修改 `10.88.0.254`。
- 基线：生产仍为 `精准稳定-v1-r3.yaml`。
- 目标：在不改变国内直连、支付固定出口和现有业务菜单结构的前提下，降低“通用测速正常但具体业务打不开”的概率。
- 边界：R4-HA 提升的是配置正确性、业务探测能力和故障恢复速度，不承诺端到端 `99.999999%` 可用率。

## 核心变化

R4-HA 增加四个独立的 `url-test` 业务节点池：

| 业务 | 默认节点池 | 探测地址 | 间隔 | 回退 |
| --- | --- | --- | ---: | --- |
| ChatGPT | `🤖 ChatGPT 专用节点池` | `https://chatgpt.com/cdn-cgi/trace` | 900 秒 | `🛟 稳定自动` |
| Claude | `🟠 Claude 专用节点池` | `https://claude.ai/favicon.ico` | 900 秒 | `🛟 稳定自动` |
| Gemini | `🔵 Gemini 专用节点池` | `https://gemini.google.com/` | 900 秒 | `🛟 稳定自动` |
| Netflix | `🎥 Netflix 专用节点池` | `https://www.netflix.com/` | 900 秒 | `🛟 稳定自动` |

四个池覆盖全部有效订阅节点并过滤流量、到期、官网、邮箱和订阅更新提示。业务组仍能直接切换 `DIRECT`、稳定自动、自动选择、手动选择及八个国家组，但默认第一项改为对应专用节点池。

## 故障约束

1. 专用池不得包含 `DIRECT`，避免检测故障时暴露真实出口。
2. 专用池必须引用 `🛟 稳定自动`，订阅节点暂时为空时仍有非直连回退链路。
3. 支付、汇款和交易平台继续走手动选择或固定出口，不按最低延迟自动漂移。
4. 真实业务探测为低频健康信号，不等同于账号登录、地区权益、支付风控或完整 API 能力验证。
5. OpenClash 保存的历史选择必须在切换时按“组名与语义”恢复；节点已不存在时回到该组的新默认值，不能保留空引用。

## 配置拓扑

```text
具体业务规则
├─ ChatGPT ──> ChatGPT 专用节点池 ──┐
├─ Claude ───> Claude 专用节点池 ───┤
├─ Gemini ───> Gemini 专用节点池 ───┼─> 稳定自动 ─> 自动选择 ─> REJECT
└─ Netflix ──> Netflix 专用节点池 ──┘

国内域名/IP ─> DIRECT
支付/交易 ───> 手动选择（固定出口）
其他海外 ────> 隐私代理 ─> 稳定自动
```

## 为什么不等于八个 9

业务池只能控制节点选择。终端、局域网、旁路由、DNS、爱快双 WAN、运营商、订阅供应商、目标网站、账号和风控系统仍可能独立故障。R4-HA 的验收目标是“已知规则与引用 100% 正确、候选切换可回滚、关键业务连续通过测试”，不是用配置文件承诺无法测量的公网 SLA。
