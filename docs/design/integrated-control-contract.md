# 进源Clash Center 0.3：完整接管与隔离契约

本文是实施契约，不是已上线声明。生产状态以独立验收和最终部署记录为准。

## 产品与操作

面向当前局域网管理者，沿用用户提供的 Logo、原生 HTML/JS/CSS 与 Python 后台。目标是一次登录完成日常订阅、节点、分流、DNS 和监控管理。页面采用现有浅色、克制、清楚的后台风格；常用操作直接可达，高级参数逐步展开。主导航包括总览、分流、节点、订阅、DNS、监控、诊断、备份和活动。状态必须说明数据时间、测量位置和限制，未知、过期、失败不可转换成绿色成功。

保持已有 CSS token 和通用表格、状态标签、表单、弹窗、任务反馈组件；不添加前端框架、外部字体或 CDN，不为每个模块复制认证和调度框架。移动端保留完整操作并允许表格内部滚动，页面本身不横向溢出。轮询保留未提交表单、筛选、焦点和草稿。

## 单一控制与认证

统一会话负责所有管理操作，同源和 CSRF 校验用于写入。模块通过有限任务队列、执行前 revision 核对、跨进程 routing-owner 锁和结果读回完成变更。一个模块超时不能阻塞总览或覆盖其他模块结果。现有原生自建节点解析和发布实现复用，不复制另一个节点管理器。

Kuma 使用原有合法账号完成一次后台绑定，保存官方签发的 JWT，后续由受限本机桥接访问其认证接口。密码和 TOTP 只在内存和私有桥接输入中使用，不保存到任务、审计或响应；JWT 仅保存在权限受限的持久化目录，不返回浏览器。失效后由统一中心管理员重新绑定，不重置原账号、不关闭 Kuma 自身认证。正式融合验收后精确移除对外 3101 端口；内部监控引擎继续运行，现有监控和通知配置保持。

## 订阅生命周期与候选隔离

信息来源与节点来源仍是不同阶段，但自动对账连接它们。新增来源经过解析、去重、校验、隔离检测、准入、受控发布和 Clash 加载读回。每个来源保留独立状态、失败证据和重试时间。原有显式 provider 的 ID 与拉取地址不因本次迁移改变。

候选不加载到生产 Clash：即使普通组不引用候选，内置 GLOBAL 仍可能使其可见。候选只进入私有缓存和独立 loopback 检测内核。通过准入的新增来源由固定 `Managed_Auto` provider 发布，中心展示其来源映射；不声称每家机场都对应独立 Clash provider。

中心对来源的停用和删除须持久化本地意图，避免下一次导入将其复活。仍被选择链使用或可见性不足的节点保留为待退役，不能为完成删除改动业务选择。单个来源失败不得删除该来源已接受节点；其缓存无效时冻结并告警。确认故障后的 1 小时冷却和自动复测语义保留。

发布事务期间，只通过 249 统一中心修改策略，不同时使用原生 OpenClash/Mihomo 面板或其他直连 API 客户端切换。统一入口的写操作参与同一协调锁；绕过该入口的外部写入无法与本地文件事务原子协调。控制器在多个阶段检测选择变化并保留事务证据，发现变化则延迟/拒绝接受，但不能把这些检查宣传为对任意外部并发的绝对原子保证。页面应在发布区醒目显示此维护约束，不能默认用户已知。路由器原生管理访问保留作维护与恢复，不在本轮未经依赖核验就封禁整个局域网的控制 API。

## DNS 管理与检测边界

本次上线保留 Corefile 原字节和初始解析行为。为未来原子应用，部署可将只读单文件挂载迁移到受保护目录挂载，但必须逐字复制、独立验证、保留旧源和回退所有权；禁止在单文件 bind 上假定 rename 可以可靠生效。

DNS 上游、主机记录和重写规则使用草稿、预览、验证、受控应用、实际解析核验和回退。页面读取不生成配置迁移。没有经过运行验证的 writable/validator/reloader/probe 能力，不开放应用按钮。以后明确的 DNS 修改不能被镜像回退静默覆盖。

污染检测结合预期本地记录/Fake-IP、不同解析路径、错误类型和连接/TLS 证据。CDN 差异不是污染证明；DNSSEC 的 resolver asserted AD 与本地密码学验证分开。浏览器、容器与指定上游视角分开记录。

多站点泄漏检测只使用已核验协议。浏览器随机探针必须由真实浏览器触发；后台仅从稳定结果端点读取，不能解析同一探针域名污染终端证据。未能验证自动接口的站点标为人工对照。没有观测、站点限流、接口变化和路径失败不得合并成“零泄漏”。检测默认本地留存、有限并发和总时间预算，不上传真实浏览历史。

## 发布门槛

代码从镜像加载，持久化目录仅承担状态、配置和历史；旧持久化代码 overlay 不得覆盖新镜像。构建不包含生产凭据或数据，不执行 docker commit，不安装无关依赖。

先在完整隔离副本验证权限、真实协议、功能、超时、并发冲突、恢复、重启持久化及资源消耗，再执行生产变更。第三家必须取得真实订阅解析、隔离检测、发布文件和 Clash 加载证据；不能用 mock、进程 healthy 或接口返回 200 替代。生产不注入破坏性故障。切换前告知影响，在线备份和独立超时回退可用后才切换；P0/P1 未关闭不得上线。
