# 可信策略控制台：候选操作说明

适用范围：P0-d8 隔离候选。不是生产安装手册，不代表任何现网已升级。

## 从哪里进入

- 原前端的“系统管理 → 可信策略”提供同一组件，但只有已配置真实 trust backend 的服务才能返回实际证据。原 `cmd/server` 并未自动接上此 backend。
- 独立候选 `image-trust-api` 可显式配置 `webDir`，指向 Vite 已构建输出的可信绝对目录，访问同源 `/trust.html`。默认空值不提供页面。不能指向源码目录或任意文件共享目录。
- Vite 输出必须包含 `.vite/manifest.json`、`trust.html` 及其可达资产。服务器只预载并提供这个 entry 的有限资源，不提供主 App、manifest 或目录列表。
- 非本机访问必须使用正常受信任 HTTPS；本机 loopback HTTP 只用于本机候选测试。不要通过非加密局域网 HTTP 输入令牌。

构建/配置是候选管理者的离线操作，页面不能替你安装依赖、创建身份、初始化 Store 或发放权限。本轮没有在用户生产主机执行这些步骤。

## 如何查看

1. 页面初始全未知、不自动请求；确认“隔离候选 / 未发布 / BLOCKED / 只读”提示。
2. 使用事先通过服务端正式认证配置取得的短期、最小权限令牌。只读日常查看建议 auditor，不要为方便而使用 admin。
3. 输入 Bearer 令牌，点击“连接并读取”。令牌仅在当前组件内存，不保存在浏览器或地址栏；共享电脑使用后必须“断开并清除”并关闭标签页。
4. 分别看目录签名时效、来源新鲜度、审计健康；它们不是同一个指标。“本地窗口内”不证明发布方没有隐藏新撤销，“已核对”不证明目标网站可访问。
5. 展开 SHA-256 查看完整值。当前策略是目录定义与 grant 观察状态，不是部署记录；AVAILABLE 不能当成业务已验证成功。
6. 记录按追加顺序从旧到新。策略搜索覆盖本次已读取的整个策略集合；记录搜索只覆盖当前页，默认 20 条。不要把当前页搜索空结果理解为全库没有记录。
7. “手工刷新”重读当前记录页；若 sequence 变动返回 409，记录清空并回到第一页，再点击手工刷新。不会自动重试验证、续 grant 或重放业务。
8. 本页没有网络轮询。时效会本地自动降级；需要新证据时手工刷新。切回挂起标签页也会重新计算陈旧程度。

## 状态与处理边界

| 显示 | 表示 | 可以做什么 |
|---|---|---|
| 未知 / 尚未读取 | 没有认证读回证据 | 检查候选来源后显式连接 |
| 401 / 凭据无效 | 服务没有接受该令牌；所有旧观察已清除 | 按正式身份流程取得新令牌，再连接 |
| 403 / 记录无权限 | viewer 等角色不能看操作历史 | 若工作职责确实需要，向身份管理员申请 auditor；不绕过 RBAC |
| 409 / 快照变化 | 翻页期间持久状态变化 | 回第一页手工刷新；不拼接旧页 |
| 超时 / 503 / 格式无效 | 当前无法取得可相信的证据 | 保持未知，查候选日志/完整性/连通性；不关闭校验换绿 |
| 来源未启用 | 未配置 P0-d7 强制来源刷新 | 不能解释为外部来源已新鲜 |
| 陈旧 / 未确认 | 本次证据超过相应窗口或条件不成立 | 手工读取新观察；不能重建坏库或强制授权 |
| 本次启动补审计 N | 健康持久状态中有 N 个审计缺口已对账 | 看实际记录；不是恢复了 N 项业务、不是 HTTP 成功送达证明 |
| 时间未知 | 该事件尚无已持久绑定的真实审计时间 | 不用截图时间或当前时间补造 |

## 记录、备份与回退

- 真实操作事实仍在受管 trust Store 的 journal 和独立 evidence Store；页面不创建第三份权威状态。读取不会追加操作记录或消费 grant。
- 本阶段的浏览器验收报告和截图属于 CI 工件，不是生产备份。报告保留源码提交、运行编号和边界；不归档 ready.json、令牌、私钥、身份配置或浏览器 profile。
- 没有执行生产变更，因此没有一份新的“已做生产备份”可供承诺，也不需要用户切 DNS 或网络。现有生产备份保持原状。
- 本阶段代码回退须在独立开发分支按实际提交选择 revert；它不等于可回滚 trust catalog 的 generation 或已消费 grant。不得恢复旧信任数据库来撤销防回放事实。
- 真正上线需另行授权、先备份受影响的配置/状态并验证恢复方案，再做候选灰度、生产读回和浸泡。本说明不解除该流程。

功能/安全边界见 [实施合同](P0D8-IMPLEMENTATION-CONTRACT.md)。验收必须查当次实际执行记录，不能只看本说明或测试数量。
