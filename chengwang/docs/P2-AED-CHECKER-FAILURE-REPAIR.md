# aed 实际失败：检查器边界修正候选

本候选以 `aed4712253f840d1c68b2482bd0c0edf4fa4e7f4` 为基线，仅修正隔离验收工具。未修改前端、Go 服务、浏览器版本、生产、main 或正式 Registry。

## 原提交实际验收

aed 的父门、镜像绑定、订阅读回、原生探针工作流成功；订阅 UI 和探针浏览器工作流失败。父门上传的两份原始 Go JSON 已按原严格 CLI 离线重算：普通／race 各 2709 项语义事件通过；前端原始报告中 18 个结果文件、345 项断言全部通过。格式报告显示无需修改。以上均是 aed 的证据，不自动归属于后续提交。

订阅 UI 的八个旧 producer 及八个 fresh 通过。两个默认能力配置的 producer／fresh 通过；两个配置了后端的能力配置均在独立检查器失败。实际 driver 已完成移动端行程，不再停在先前 8e 的移动 DOM 校验；截图仍需要独立视觉审查。

## 配置说明被误当作凭据

两份配置后端的原 CLI 首拒绝均是 `validate_captures` 的粗粒度 `Bearer ` 围栏。实际两次能力正文里，只在 `real_authentication.evidence[0]` 和 `limitations[0]` 出现两条 Go 注册表中的静态完整说明，并非运行时凭据。旧能力语义检查并未逐字冻结这些动态文字，因此不能简单删除围栏或允许所有 CAPABILITIES 文本。

候选仅识别 Git 指定提交里唯一、受条件控制的身份说明源块，校对两条已知完整安全字面。能力正文先经过完整既有语义校验，再按解码后的字符串及精确字段位置检查。只有指定配置、指定能力 ID、指定数组索引且完整字面一致时容纳说明中的 `Bearer `；追加令牌、换 ID／字段、额外文字、伪造调用方字典及布尔索引仍拒绝。PRIVATE KEY、认证头、哈希和原件来源等检查保留；既有 ASSET 静态源码例外不扩展到其他 API。

新增 22 项专门 CPU 用例作为独立增量接入 CI，不混入旧 188 合同，不改旧 50 个检查器方法及其名单。最终候选还对四个配置／引擎的八份实际能力正文完成窄围栏复算；它是新检查器审核历史字节，不能改称原 aed CLI 已通过。

## 浏览器证据的源码清单上下文

两引擎主浏览器原 CLI 均在读取 browser-build.json 时拒绝：实际顶层源码清单有 1037 项，但入口仍使用默认 1024 数组上限。内部 native 后端验证已通过；该失败发生在后续浏览器语义之前。

候选只在五个检查器的八个确切 browser-build／isolation 解码调用启用既有源码清单上下文，保持通用 1024、两顶层清单 2000、原字节／深度及 source_list 语义边界不变。四个旁证入口也逐一接齐。

107 项受影响既有 CPU 方法通过。候选对两引擎各主检查器加四个旁证实际复算共十次：五次通过、五次拒绝。Playwright 主检查器和两引擎的 status／binding 旁证通过；CDP 主检查器继续因真实 failedRequests=1 拒绝。另四次 network／identity 拒绝来自保留的当前检查器与历史提交字节身份绑定，未被跳过。后续同提交 CI 才能完成这些来源绑定。

## 仍保留的真实 CDP 失败

CDP 原件有一条 30 秒轮询状态请求：200 响应，455 字节正文及 EOF 均已观察，但网络终态报告取消；JS 信号为未取消，未见对应 ABORT／CANCEL／CLEANUP 观察，后续轮询正常。本记录不把它猜成页面卸载或正常关闭，不清零计数，不放宽原八零门。

该探针实际使用 Chrome 155，与能力页的 Chrome 157 是不同版本。已查得官方 Fetch 修复提交 `62473ad0f747e245e514c93e741bb8e168a2a207`，其机制与完整正文被报告取消的现象相关。固定源比对和隔离浏览器版本对照另行记录；这不是本次内部调用栈证明，本候选没有升级浏览器或声称该问题已经修复。

## 本候选退出条件

- 新提交的独立 22 项 CI 辅助门及既有 188 项门实际通过。
- 两配置、两引擎的能力 producer 和 fresh 均按新提交独立复算。
- 探针主门和四旁证按同一新提交重跑，原身份绑定不绕过。
- CDP 的实际取消独立诊断及版本对照，成功标准仍保留真实计数和原件；不以其他成功项抵消。
- 实际证据总览的新 driver／checker／CI、整套功能基线、恢复、灰度及生产读回仍按台账推进；本候选不构成完整系统上线。
