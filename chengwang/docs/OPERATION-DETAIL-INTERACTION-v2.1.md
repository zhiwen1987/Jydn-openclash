# 页面目标

用户进入任意一条操作记录后，应在不阅读原始日志的情况下回答：

1. 为什么发生这次操作。
2. 谁发起、谁批准、谁实际执行。
3. 操作影响了哪些对象、业务和用户。
4. 系统计划做什么，设备实际发生了什么。
5. 哪一步失败、为什么停止扩大。
6. 是否完成补偿或回滚。
7. 真实业务是否恢复，证据是否仍然有效。
8. 当前还有什么风险，下一步由谁负责。

# 页面信息结构

## 1. 页面头部

固定展示：

- 操作名称和操作ID。
- 最终状态及状态解释。
- 追踪ID、风险等级和所属环境。
- 发起来源、真实操作者和代表身份。
- 开始、结束、总耗时和时区。
- 受影响业务、站点、对象数和用户范围。
- 当前版本、目标版本和最终生效版本。

主要动作：

- 基于当前状态创建新草稿。
- 导出脱敏证据包。
- 复制操作深链接。

禁止提供“重新执行旧命令”。

## 2. 阶段轨道

阶段顺序固定为：

```text
请求
→ 预检
→ 审批或安全门禁
→ 排队
→ 执行
→ 设备读回
→ 技术验证
→ 业务验证
→ 稳定性观察
→ 提交、补偿或回滚
→ 最终验证
→ 关闭或人工接管
```

每个阶段同时显示：状态、开始和结束时间、负责组件、关键结果、是否消耗预算。阶段状态使用文字和图标，不只使用颜色。

点击阶段后，时间线定位到对应事件；键盘左右键可以切换阶段。

## 3. 执行事件时间线

时间线是页面主区域。每条事件展示：

- 可信时间、设备时间和接收时间。
- 阶段、执行主体和目标稳定ID。
- 自然语言动作摘要。
- 脱敏输入摘要和输出摘要。
- 尝试次数、耗时和结果。
- 证据、审批、差异或错误详情入口。
- 父事件、子事件和关联追踪ID。

默认折叠正常的重复步骤，保留完整计数；失败、重试、状态未知、补偿、回滚和人工动作默认展开。

时间线提供：

- 全部事件。
- 仅异常。
- 仅配置变化。
- 仅业务影响。
- 仅人工操作。
- 仅外部漂移。

过滤不会改变原始记录，也不会影响导出证据的完整性。

## 4. 状态对比

固定使用四列：

1. 变更前实际状态。
2. 目标状态。
3. 执行后实际读回。
4. 补偿或回滚后的最终状态。

每个字段标记：一致、不同、缺失、未知、已脱敏或不适用。差异显示结构化字段，不默认展示整份原始配置。

用户提交值不得冒充实际生效值。只有设备或数据面的独立读回才能进入“实际读回”列。

## 5. 验证结果

验证按四层展示：

- 配置验证：版本、字段和实际读回一致性。
- 技术验证：DNS、TCP、TLS、HTTP、路由和性能。
- 业务验证：真实业务事务及成功标准。
- 稳定性验证：观察窗口、复发和新增异常。

每项验证显示探针位置、网络路径、证据时间、有效期和独立性等级。不同验证器结论矛盾时显示“结论冲突”，不能汇总成绿色成功。

## 6. 右侧操作概览

右侧固定栏包含：

- 操作原因和关联事件、事故、工单。
- 审批链、附加条件和职责分离结果。
- 安全监督器决定和拒绝原因。
- 动作预算、调查预算及消耗。
- 最大影响范围、实际影响范围和停止条件。
- 恢复点、补偿动作和回滚结果。
- 审计链完整性和最近独立校验时间。
- 残余风险、未完成事项和下一负责人。

窄屏时右侧栏变为可展开抽屉，但关键状态、停止和接管入口不能隐藏。

# 完整状态模型

## 正常状态

- 已请求。
- 预检中。
- 等待审批。
- 已批准。
- 排队中。
- 执行中。
- 读回中。
- 验证中。
- 观察中。
- 成功且已验证。

## 异常和恢复状态

- 已拒绝。
- 已取消且未产生变更。
- 安全停止中。
- 部分成功。
- 状态未知。
- 补偿中。
- 补偿失败。
- 回滚中。
- 已回滚并验证恢复。
- 回滚失败。
- 救援模式。
- 人工接管。
- 外部漂移。

任何异常状态都必须给出影响、系统已经做过的事情、下一安全动作和责任人。

# 关键交互

## 基于当前状态创建新草稿

1. 重新读取目标实际状态。
2. 检查旧操作的证据是否过期。
3. 复制可复用的业务意图，不复制旧命令、旧凭据和旧审批。
4. 重新计算差异、影响、权限、预算和回滚点。
5. 生成具有新操作ID和追踪ID的草稿。

## 导出证据包

1. 选择用途和导出范围。
2. 系统按权限执行字段脱敏。
3. 显示将包含和排除的内容。
4. 高敏感导出进入审批。
5. 生成签名、摘要、时间、版本和校验清单。
6. 导出行为本身写入操作记录。

## 安全停止

如果操作仍在运行，页面区分：

- 冻结后续批次。
- 在当前安全点停止。
- 执行补偿并停止。
- 紧急冻结所有自动写入。

界面必须说明每种动作会继续什么、停止什么、是否影响数据转发以及如何恢复。

## 人工接管

接管前显示当前锁、租约、正在运行的步骤和状态未知目标。接管产生新事件，原自动化进入暂停，不能与人工同时写同一目标。

# 刷新、弱网和多人协作

- 页面只读取服务端任务状态，不在浏览器中执行任务。
- 刷新、断线和重新登录后恢复同一追踪ID和阅读位置。
- 数据过期时显示最后更新时间，禁止依赖旧证据发起新动作。
- 同一操作被他人接管、审批或停止时实时显示操作者和时间。
- 旧页面提交动作时使用版本前置条件；冲突后必须重新读取和确认。
- 链接分享保留对象和时间线位置，但不绕过接收人的权限检查。

# 权限与敏感信息

## 可见性层级

- 摘要权限：查看自然语言结果和业务影响。
- 技术权限：查看步骤、差异、探针和设备读回。
- 敏感权限：查看受控字段、导出证据或访问短期原始输出。
- 审计权限：验证签名、序列和独立审计副本。

无权限内容显示“需要相应权限”，但不泄露对象存在、字段长度或原始错误内容。

## 禁止记录

- 密码、令牌、私钥和Cookie。
- 完整授权头和未脱敏连接串。
- 与判定无关的响应正文和个人数据。
- 可以直接复制执行的高风险原始命令。

# 数据对象

页面由以下只读视图对象组成：

- `OperationSummary`：操作概览和最终状态。
- `OperationStage`：阶段状态和预算。
- `OperationEvent`：追加式执行事件。
- `ActorIdentity`：真实身份、代表身份和来源。
- `ApprovalDecision`：审批与附加条件。
- `GuardDecision`：安全监督器决定。
- `StateSnapshot`：变更前、目标、读回和最终状态。
- `VerificationResult`：四层验证结果。
- `RecoveryPoint`：备份和恢复能力。
- `EvidenceReference`：证据位置、摘要、有效期和完整性。
- `ResidualRisk`：残余风险和下一负责人。

对象通过稳定ID、版本和追踪ID关联。UI不直接拼接多个系统的自由文本作为真相。

# 无障碍与显示规则

- 全部操作支持键盘，阶段轨道和时间线有明确焦点顺序。
- 状态使用文字、图标和形状，颜色只作为辅助。
- 时间线可以切换为表格视图。
- 支持200%缩放和减少动画。
- 屏幕阅读器能够读出阶段、结果、风险和折叠状态。
- 长ID允许复制但默认截断，完整值通过可访问名称读取。

# 页面验收

1. 用户在30秒内能够说明操作原因、失败步骤、最终状态和恢复结果。
2. 变更前、目标、实际读回和最终状态不会混淆。
3. 失败、重试、补偿和回滚事件全部保留且顺序可信。
4. 页面刷新和断线不丢任务、不重复执行、不改变最终状态。
5. 多人操作不会覆盖新状态，接管和审批均有明确身份。
6. 状态未知和验证冲突不能显示为成功。
7. 旧操作不能直接重放，创建新草稿必须重新预检。
8. 敏感字段不会出现在页面、搜索索引、导出和前端错误中。
9. 导出证据包可以独立校验，并记录导出者和用途。
10. 键盘、屏幕阅读器、缩放和非颜色状态表达通过验收。
11. 操作记录与独立审计链可以通过事件ID相互验证。
12. 当前页面所有数据都能追溯到真实对象、版本和证据来源。

# 后续页面

选定的操作详情页与以下页面组成完整流程：

```text
操作记录中心
→ 单次操作详情
→ 阶段或事件详情
→ 差异 / 审批 / 验证 / 恢复点
→ 基于当前状态创建新草稿
→ 新任务预检和审批
```

只有上述流程、异常状态和权限状态完成交互原型后，才能进入前端实现。
