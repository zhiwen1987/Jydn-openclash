## 产品目标

澄网是一套面向大型企业的多内核网络控制与自治平台。平台以业务意图为入口，统一管理精准分流、代理出口、反向代理、API网关、DNS、隧道、零信任、节点能力评估、配置发布、自动修复和审计证据。

平台不把任一代理内核的配置格式作为系统真相。业务策略先进入统一领域模型，再由适配器编译为各数据面的配置。数据面组件可以替换，业务策略、审计记录和发布流程不得随内核替换而丢失。

## 核心原则

1. 控制面与数据面分离。
2. 业务意图与内核配置分离。
3. 期望状态、实际状态和观测状态分离。
4. 所有生产变更必须有版本、证据和回退路径。
5. 控制面失效时，数据面继续使用最后已知可用配置。
6. 测速结果不等于互联网可用，互联网可用不等于业务可用。
7. 无法观察或无法确认的结果必须标记为未知，不得伪装成精准判断。
8. 自动修复必须受到权限、动作预算、冷却时间和影响范围约束。
9. AI只提供有证据的分析；高风险变更不得由AI独立执行。
10. 不设计绕过未授权防火墙、规避企业审计或伪装成无关业务的能力。

# 系统分层

## 体验平面

提供Web控制台、拓扑大屏、API、CLI、移动端只读视图和ChatOps入口。所有入口使用同一权限、审计和版本模型。

## 意图与控制平面

负责业务策略、路由意图、规则冲突分析、策略模拟、配置编译、审批、版本、发布、回滚和漂移检测。

## 数据平面

首批支持Mihomo、sing-box和Xray；反向代理与API场景通过Envoy、NGINX、HAProxy或APISIX适配；DNS通过CoreDNS、Unbound或企业DDI适配；组网通过WireGuard、OpenVPN、IPsec或授权的零信任连接器适配。

## 身份与信任平面

管理用户身份、设备身份、工作负载身份、证书、短期SSH凭据、密钥引用、零信任授权和紧急访问。

## 可观测与证据平面

收集指标、日志、链路、流量、DNS结果、配置状态、业务探针和事故事件。证据必须携带来源、采集时间、有效期和可信度。

## 自动化平面

执行SSH、HTTPS和设备API任务，负责预检、备份、部署、读回、冒烟、灰度、回滚、巡检和低风险自动修复。

## 治理平面

负责多租户、权限、审批、审计、合规、成本、容量、许可证、数据保留和供应链治理。

# 统一领域模型

## 三种状态

系统必须同时保存：

- 期望状态：管理员批准后希望系统达到的状态。
- 实际状态：从设备、内核或外部平台读取到的真实配置。
- 观测状态：探针、日志和真实业务请求反映的运行结果。

三种状态不一致时不得简单覆盖，必须先识别原因并产生漂移事件。

## 核心对象

- 集团、租户、区域、站点、网络区域。
- 设备、接口、线路、运营商、ASN、地址空间、VRF和VLAN。
- 用户、部门、角色、设备身份和工作负载身份。
- 应用、业务分类、域名集、IP集、端口集和协议集。
- 节点、订阅、节点池、出口、反向代理和隧道。
- DNS区域、解析策略、上游、缓存和健康状态。
- 策略、规则、动作、例外、继承关系和人工锁定。
- 草稿、版本、发布批次、审批、回滚点和验收报告。
- 证据、事件、告警、事故、处置动作和审计记录。

每个对象必须使用稳定内部ID。显示名称允许变化，但不得通过名称维持引用关系。

# 精准分流

## 规则层级

规则按以下层级执行：

1. 强制安全与阻断规则。
2. 法规和企业合规规则。
3. 关键业务固定出口规则。
4. 自定义业务规则。
5. 国内精确规则。
6. 国外业务规则。
7. 区域、运营商和网络规则。
8. 用户或部门覆盖规则。
9. 默认互联网策略。

高层级规则可以锁定，低层级规则不得覆盖锁定结果。

## 匹配条件

- 精确域名、域名后缀、关键字和正则表达式。
- GeoSite、IP CIDR、GeoIP和ASN。
- 来源IP、MAC、用户、设备、部门、租户和站点。
- 目标端口、传输协议、应用协议和进程。
- 入站、网络区域、时间、工作日和维护窗口。
- DNS上游、解析结果、出口地区和节点能力标签。
- AND、OR、NOT和嵌套条件组。

## 决策证据

每次策略模拟和可观测连接应能够解释：

- 输入上下文。
- 命中的层级和规则。
- 被排除的候选规则及原因。
- 使用的DNS路径。
- 候选节点、排除节点及排除原因。
- 最终动作、节点、出口和回退路径。
- 配置版本和证据时间。
- 结果可信度及未知项。

## 发布前分析

- 重复规则。
- 规则冲突。
- 阴影规则。
- 永远不可达规则。
- 循环引用。
- 空节点池。
- 无有效回退。
- IPv4与IPv6结论不一致。
- DNS与流量出口不一致。
- 跨内核语义损失。
- 对关键业务和关键用户的意外影响。

# 节点能力与稳定性评估

## 评估层级

1. 进程与端口健康。
2. ICMP、TCP和UDP连通性。
3. TLS、QUIC和HTTP协议能力。
4. DNS解析与路径一致性。
5. 吞吐、丢包、抖动、重传和MTU。
6. 出口IP、ASN、国家、运营商和稳定度。
7. 真实业务能力。
8. 用户体验与历史稳定性。

## 业务结果状态

- 可用。
- 部分可用。
- 地区受限。
- 认证受限。
- 账号限流。
- 出口IP受限。
- DNS异常。
- TLS异常。
- 网络超时。
- 服务端异常。
- 未评估。
- 评估结果过期。

HTTP 403和429不得直接判定为网络可用或网络故障，必须结合目标、响应特征、账号状态和其他探针解释。

## 节点评分

综合评分至少考虑：

- 业务成功率。
- 连续稳定时间。
- P50、P95和P99延迟。
- 丢包、抖动和重传。
- 出口IP稳定度和历史风险。
- 最近故障次数和恢复速度。
- 最近切换惩罚。
- 地区和业务适配度。
- 评估证据的新鲜度。

## 防抖与恢复

状态机采用：正常、轻度退化、连续失败、隔离观察、确认故障、切换、恢复探测、小流量验证、正式恢复。

每个节点池必须定义失败阈值、恢复阈值、冷却时间、最短保持时间、单位时间最大切换次数和恢复灰度比例。

# DNS与DDI

## DNS路径

- 企业内部域名进入内部权威DNS。
- 中国大陆域名进入国内递归路径。
- 境外业务域名进入授权的加密DNS路径。
- 关键业务可以配置专用解析路径。
- 未知域名进入安全默认路径。

## 必须支持

- UDP/TCP DNS、DoH、DoT和DoQ。
- DNSSEC验证。
- 分视解析和内部域名。
- 缓存、预取、负缓存和缓存刷新。
- 上游独立健康检查和故障切换。
- IPv4、IPv6、NAT64和DNS64策略。
- Fake-IP、真实IP和兼容模式。
- 浏览器或终端绕过企业DNS的检测。
- DNS泄漏检测。
- DNS结果与实际出口一致性验证。
- DHCP、IPAM和地址冲突集成接口。

DNS切换不得作为孤立操作，必须同时验证解析结果、路由出口、TLS和真实业务。

# 代理、反向代理、API网关与隧道

## 正向代理

- 多内核、多实例和混合版本。
- TUN、TProxy、Redirect、Mixed、SOCKS和HTTP入站。
- 手动、自动、故障转移、负载均衡和链式代理。
- 连接排空、会话黏性和优雅切换。
- 按用户、设备、应用和业务选择出口。

## 反向代理与API网关

- HTTP/1.1、HTTP/2、HTTP/3、WebSocket、gRPC、TCP和UDP。
- TLS终止、证书自动轮换和双向TLS。
- 主机、路径、请求头和身份路由。
- 负载均衡、健康检查、重试、超时和熔断。
- 限流、配额、缓存、请求转换和流量镜像。
- 蓝绿、金丝雀、A/B和按比例分流。
- API认证、消费者、密钥和调用审计。
- AI模型代理、模型路由、Token预算和敏感信息控制接口。

## 隧道与零信任

- Site-to-Site、远程接入、子网路由和出口节点。
- 用户、设备、姿态、应用和工作负载联合授权。
- 每应用访问，而不是默认开放整个网段。
- 多连接器、精确前缀冗余和故障转移。
- 重叠地址空间和租户路由域。
- 仅支持企业授权环境中的安全传输和审计。

# 多内核适配

每个适配器必须声明：

- 支持的内核和版本范围。
- 支持的协议、规则、DNS和入站类型。
- 是否支持热加载、回滚、会话排空和实时查询。
- 是否支持IPv6和双栈。
- 最大规则量、节点量和并发边界。
- 原生支持、转换支持、降级支持和不支持的能力。
- 已知风险、弃用状态和安全状态。

不支持的能力必须阻止发布、明确降级或切换兼容数据面，不得静默丢弃。

# 发布与回滚

## 发布状态机

```text
草稿
→ 静态校验
→ 语义校验
→ 依赖检查
→ 策略仿真
→ 审批
→ 备份
→ 预发布
→ 金丝雀
→ 观察
→ 分批扩大
→ 全量
→ 持续验收
→ 完成
```

任一阶段失败后必须停止扩大、冻结证据、自动回滚、验证恢复并创建事故记录。

## 独立版本对象

- 业务策略版本。
- DNS版本。
- 内核配置版本。
- 节点订阅版本。
- 证书版本。
- 设备系统版本。
- 适配器版本。
- 健康检测标准版本。
- AI模型与提示配置版本。

## 配置漂移

系统定期读回设备和内核实际状态。漂移事件必须区分人工变更、外部系统变更、设备自恢复、发布不完整和未知来源。人工锁定对象不得被自动协调器静默覆盖。

# 高可用与故障模型

## 控制面失效

- 数据面继续使用最后已知可用配置。
- DNS继续使用有效配置和本地缓存。
- 分支保留本地探测和有限自治能力。
- 新发布冻结。
- 审计事件本地排队并在恢复后补传。
- AI降级为只读或停止。

## 单一写入者与脑裂保护

- 同一目标同一时间只有一个有效租约持有者。
- 配置使用全局单调版本。
- 数据面拒绝旧版本覆盖新版本。
- 无法确定领导者时冻结写入。
- 紧急接管必须双人确认并留下审计证据。

## 故障域

节点和线路必须标记运营商、ASN、机房、云区域、宿主机、电源、DNS上游和代理供应商。高可用选择必须验证故障域独立性，避免多个备用节点实际共用同一上游。

## 有状态业务

支付、交易、会议、数据库和长连接业务支持固定出口、连接排空、会话保持和受控切换。系统不得仅因为延迟更低而自动改变关键业务出口。

# 自动化与自动修复

## 自动化执行链

发现目标、验证身份、读取现状、生成备份、计算差异、执行预检、下发变更、读回对账、业务冒烟、观察、提交结果或回滚。

## 自动修复级别

- L0只观察：收集证据和生成诊断。
- L1低风险自动修复：重试探针、隔离故障节点、清理过期缓存、恢复已验证订阅。
- L2受控自动修复：切换单个非关键业务、撤销新规则、恢复最后有效配置；必须有影响上限和自动回滚。
- L3高风险变更：全局DNS、默认路由、身份策略、支付出口、全网升级和删除操作；必须人工审批。

## 动作保护

每种自动动作必须定义权限、适用对象、最大影响范围、冷却时间、每日预算、前置证据、成功标准和回滚动作。

# AI治理

## AI可以执行的职责

- 故障归因候选。
- 证据关联和矛盾提示。
- 规则解释和冲突说明。
- 配置草稿和测试用例生成。
- 影响分析、容量预测和异常检测。
- 生成受控处置草案。

## AI不得独立执行的职责

- 改变全局默认路由。
- 改变核心DNS路径。
- 修改身份和信任根。
- 切换支付或交易出口。
- 删除配置、证书或审计数据。
- 执行无法验证和无法回滚的动作。

## AI安全要求

- 日志、域名、设备备注和响应正文均视为不可信输入。
- AI只能通过受限工具访问结构化对象。
- 任何对象引用必须使用真实内部ID。
- 执行前重新读取当前状态和关键证据。
- 每个结论显示证据、时间、有效期、置信度、反证和未知项。
- 决策校验和发布门禁由确定性逻辑完成，不由语言模型代替。

# 身份、权限和审计

## 角色

- 平台管理员。
- 网络管理员。
- 安全管理员。
- 应用负责人。
- NOC值班人员。
- 审批人员。
- 审计人员。
- 只读观察者。

权限同时受租户、区域、站点、对象类型、操作类型、环境和时间限制。生产权限与测试权限必须分离。

## 凭据

- 优先使用短期SSH证书、工作负载身份和动态凭据。
- 长期密码不得写入配置、日志或任务结果。
- 密钥使用引用，不在业务数据库保存明文。
- 证书和密钥轮换必须在到期前验证，并保留恢复路径。

## 紧急访问

Break-glass访问需要双人控制、短时有效、限定目标、强制录像或命令审计，并在使用后自动吊销和复盘。

## 操作记录

人工、AI、自动化、API、CLI、适配器和设备外部变更统一进入操作记录。记录包含真实操作者、来源入口、操作原因、目标对象、变更前后、审批、安全门禁、执行步骤、实际读回、验证、回滚点和最终结果。

操作记录采用追加事件，不允许用最终状态覆盖失败、重试、补偿、回滚和人工接管过程。全局、对象、用户、任务和事故均提供可筛选时间线，并能够从业务结果追溯到实际设备变更。

密码、令牌、私钥和敏感正文不得进入记录；查询和导出操作记录本身也需要授权、脱敏和审计。可信性、保留和防篡改要求遵循[企业级闭环补强方案 v2.1](ENTERPRISE-CLOSED-LOOPS-v2.1.md)。

# 多租户与组织模型

层级采用集团、子公司、区域、站点、网络区域、设备和应用。集团策略允许向下继承，子级只能在授权范围内覆盖；锁定规则不可覆盖。

不同租户允许存在重叠地址空间，通过VRF、网络命名空间或等效路由域隔离。共享服务必须显式授权并记录跨租户访问。

# 可观测性与事件管理

## 遥测

- 指标：资源、连接、流量、DNS、节点、发布和业务SLO。
- 日志：控制面、适配器、数据面、DNS、身份和自动化。
- 链路：从用户、DNS、入口、出口到目标业务。
- 事件：配置、告警、事故、审批、执行和恢复。

## 事件证据

每条证据必须包含来源、对象、采集时间、接收时间、有效期、完整性状态和可信度。不同设备时间不一致时，应显示时钟偏差并避免生成伪精确时间线。

## 告警治理

- 区分症状、原因和推测。
- 支持去重、聚合、抑制、维护窗口和依赖降噪。
- 关键告警关联受影响用户、站点、应用和最近变更。
- 告警恢复后保留完整状态变化和通知历史。

# 供应链与插件安全

- 二进制、镜像、升级包和规则包必须校验签名或受信摘要。
- 保存软件物料清单和依赖漏洞状态。
- 订阅进入隔离区，完成格式、大小、引用、协议和恶意内容检查后才能使用。
- 插件采用最小权限和隔离执行。
- 插件接口版本化，声明兼容范围和弃用期限。
- 被撤销或存在高危漏洞的版本可以集中阻止发布。
- 离线升级包和回滚包必须验证完整性。

# 容量、性能与成本

部署前必须确定：站点、设备、终端、并发连接、每秒新建连接、规则、订阅、DNS QPS、遥测事件和拓扑对象上限。

资源优先级固定为业务转发、DNS和关键控制、健康检测、关键遥测、普通日志、可视化动画。监控或界面故障不得拖垮数据转发。

系统提供容量趋势、许可证消耗、线路和代理成本、日志存储成本及业务成本分摊。

# 灾备与恢复

## 备份范围

资产、策略、配置版本、节点和订阅元数据、DNS区域、证书元数据、密钥引用、用户权限、审批、告警、健康标准、AI记录、审计、仪表盘和适配器版本。

## 恢复粒度

- 单条规则。
- 单个业务。
- 单设备。
- 单站点。
- 控制节点。
- 数据库。
- 完整平台异地恢复。

每个恢复流程必须定义RPO、RTO、最近演练时间、恢复包完整性和恢复后业务验收。

# 数字孪生与测试实验室

生产变更前可以在隔离环境复制资产关系、规则结构、DNS逻辑、节点池结构、内核版本和业务探针。不得复制不必要的真实敏感数据。

实验室至少覆盖内核升级、订阅格式变化、节点全失效、DNS故障、WAN故障、控制面失联、数据库恢复、证书过期、规则冲突、大规模并发和脑裂场景。

## 全球拓扑交互

- 悬停约150毫秒后显示摘要卡片。
- 高亮相关路径，降低无关对象透明度。
- 点击进入站点、节点、隧道、应用、区域或事件详情页。
- 浏览器返回后恢复地图位置、缩放、图层和筛选条件。
- 拖动不触发点击；触摸设备首次点击摘要、再次点击进入详情。
- 支持键盘操作和减少动画模式。
- 大规模对象自动聚类，避免同时渲染全部链路。
- 物理、WAN、隧道、代理、DNS、业务、零信任、故障传播和变更影响分别作为图层。

## 可用性展示

可用性必须同时显示目标SLO、实际值、统计窗口、错误预算、影响用户、影响业务和数据更新时间，不得只显示一个百分比。

- 不允许AI绕过确定性校验和审批门禁。
- 不允许后台静默覆盖关键业务人工锁定。
- 不设计未授权的防火墙绕过和审计规避能力。

# 验收基线

## 功能验收

所有声明为完成的功能必须拥有真实入口、真实状态、错误处理和回滚路径，不得以演示数据代替运行证据。

## 策略正确性

- 固定测试集100%符合已批准的期望结果。
- 无空引用、循环引用和不可达关键规则。
- 已知国内、国外和业务域名得到正确决策。
- IPv4和IPv6分别验证。
- 每个结果可以解释并关联配置版本。

## 故障验收

主动模拟节点、WAN、DNS、控制面、数据库、证书和订阅故障。验证防抖、切换、回滚、告警、审计和恢复结果。

## 性能验收

在目标容量下测量控制面API、策略编译、全量发布、增量发布、DNS QPS、连接建立、遥测写入和拓扑渲染。

## 安全验收

验证越权、租户隔离、密钥保护、短期凭据、插件隔离、接口鉴权、审计完整性、提示注入和供应链完整性。

## 恢复验收

完成配置回滚、数据库恢复、控制面重建和异地恢复演练，并记录实际RPO和RTO。

## 升级验收

验证混合版本、失败升级、跨版本迁移、适配器不兼容和降级恢复。

## 用户体验验收

NOC、网络、安全、应用、审批和审计角色分别完成其核心任务；键盘操作、焦点、颜色替代信息和减少动画模式纳入验收。
