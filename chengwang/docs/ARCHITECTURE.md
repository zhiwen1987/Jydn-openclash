# 澄网架构边界

## 原则

1. **控制面与数据面分离**：澄网决定和审计策略，但数据转发由可替换的数据面适配器执行。
2. **默认失败关闭**：未配置身份、发布开关或版本前置条件时，任何写操作都被拒绝。
3. **所有发布可逆**：草稿先校验，发布产生不可变版本，适配器只能从已验证版本灰度应用。
4. **测量不等于能力**：延迟、TCP、TLS、HTTP、业务接口、账号功能是不同证据层，不相互冒充。
5. **单一写入者**：同一数据面在任一时刻只能由一个已取得租约的控制器写入。
6. **独立看门狗**：看门狗不依赖主控制面数据库，并具有严格的动作预算。

## 目标分层

```text
Web Console
    ↓ HTTPS / version precondition
Control API ── Version Store ── Audit Log
    ↓ validated desired state
Reconciler / Lease Owner
    ├─ Mihomo Adapter
    ├─ sing-box Adapter
    ├─ Xray Adapter
    ├─ DNS Adapter
    ├─ Subscription Adapter
    └─ WAN Observer (read-only initially)

Independent Probe Workers ── Evidence Store
Independent Watchdog ── bounded restart / rollback
```

## 不复用 OpenClash 的部分

- 不依赖 UCI/LuCI 状态作为领域真相。
- 不让 Shell 脚本同时承担模型、执行、恢复和审计职责。
- 不把订阅生成结果直接当作可发布配置。
- 不根据一次延迟探测自动决定真实业务可用性。
- 不允许后台静默覆盖人工锁定的关键业务出口。

## 兼容策略

Mihomo 是首个数据面适配器，但不是系统本体。sing-box、Xray 等内核通过相同生命周期接入，同时可声明自己的扩展字段。编译器生成的只是可审查片段；任何适配器必须执行：能力协商、生成、静态校验、隔离启动、业务冒烟、灰度替换、读回对账、观察窗口、自动回滚。

当前 Mihomo 适配器只完成上述生命周期中的“读取现状”和“目标与实际对账”。配置生成后的隔离启动、灰度替换、业务冒烟、观察和自动回滚仍未实现，因此不得授予生产写权限。
