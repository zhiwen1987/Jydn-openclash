# 体验目标

## 用户始终知道五件事

任何关键页面都必须回答：

1. 当前发生了什么。
2. 为什么会这样。
3. 影响了谁和哪些业务。
4. 现在可以做什么。
5. 操作失败后如何恢复。

## 操作始终满足六个条件

- 看得懂：使用业务语言，同时允许专家展开技术细节。
- 找得到：关键任务最多经过三层导航。
- 做得快：常用动作提供默认值、批量操作和模板。
- 不误操作：显示范围、影响、风险、依赖和恢复方案。
- 可中断：长流程可以保存、暂停、转交和继续。
- 可追溯：所有判断、审批、执行和恢复都有证据链。

## 复杂度渐进披露

默认先显示结论、影响和建议，再允许逐层展开：

```text
业务结论
→ 影响范围
→ 推荐动作
→ 决策证据
→ 网络与协议细节
→ 原始日志和配置
```

普通管理员不需要先理解ASN、SNI或路由表；网络专家仍能进入完整技术视图。

# 全局闭环模型

## 标准闭环

所有系统闭环统一使用以下十个阶段：

```text
观测
→ 归一化
→ 判断
→ 形成方案
→ 仿真与预检
→ 审批或授权判定
→ 执行
→ 验证
→ 结束或恢复
→ 复盘与学习
```

## 每个阶段的产物

| 阶段 | 必须产生的内容 |
| --- | --- |
| 观测 | 原始信号、来源、对象、采集时间、有效期 |
| 归一化 | 结构化事件、去重结果、关联对象、数据质量 |
| 判断 | 确认事实、可能原因、反证、可信度、未知项 |
| 形成方案 | 可选动作、预期收益、风险、影响范围、恢复方法 |
| 仿真与预检 | 规则结果、依赖检查、资源检查、兼容性和业务测试 |
| 审批 | 审批人、授权范围、有效时间、附加条件 |
| 执行 | 批次、目标、进度、返回结果、实时异常 |
| 验证 | 技术验证、业务验证、用户体验验证、观察窗口 |
| 结束或恢复 | 成功归档，或回滚、补偿、隔离和升级处理 |
| 复盘与学习 | 根因、改进项、规则调整、知识沉淀、责任与期限 |

## 闭环记录对象

每次闭环运行形成一个不可混淆的实例，包含：

- 闭环实例ID。
- 类型和触发方式。
- 关联租户、站点、设备、业务和策略。
- 当前状态和负责人。
- 开始时间、最后进展和超时点。
- 使用的证据快照。
- 决策和审批记录。
- 执行动作及幂等键。
- 验证结果。
- 回滚点。
- 最终结论。
- 后续改进任务。

# 操作闭环

## 统一任务工作台

任何会修改系统的操作都进入任务工作台，而不是直接弹出一个“确定”按钮。任务工作台固定显示：

- 操作目的。
- 当前环境和租户。
- 目标对象与数量。
- 当前版本和目标版本。
- 影响用户、站点和业务。
- 风险等级。
- 依赖项。
- 备份与回滚点。
- 当前步骤和剩余步骤。
- 负责人、协作者和审批人。

## 操作前

系统自动完成：

1. 检查权限和变更窗口。
2. 读取最新实际状态，防止使用过期页面操作。
3. 检查是否存在其他正在执行的冲突任务。
4. 生成差异和影响范围。
5. 验证目标对象可达性和凭据有效性。
6. 验证备份与回滚条件。
7. 根据风险选择直接执行、二次确认或审批。

## 操作中

- 显示整体进度和当前目标。
- 区分排队、执行、成功、失败、跳过和回滚。
- 允许安全暂停，但不允许停在未知中间状态。
- 页面关闭后任务继续运行；用户回来可恢复上下文。
- 每个目标执行使用幂等键，防止重复点击造成重复变更。
- 失去网络连接时，前端进入只读重连状态，不猜测执行结果。

## 操作后

系统必须进行：

1. 配置读回。
2. 运行状态检查。
3. DNS、TCP、TLS和HTTP技术验证。
4. 关联业务验证。
5. 观察窗口。
6. 结果归档或自动回滚。
7. 向负责人提供简明总结和详细证据入口。

## 操作结果表达

不能只显示“成功”。结果分为：

- 成功且已验证。
- 执行成功，仍在观察。
- 部分成功，需要处理剩余目标。
- 已自动回滚并验证恢复。
- 回滚不完整，进入重大事故。
- 状态未知，需要重新读取目标。
- 已取消，未产生变更。

## 操作记录

任务工作台自动生成操作记录，用户不需要额外填写重复报告。操作记录首页先回答“谁、为什么、对什么、做了什么、结果怎样”，再按需展开审批、差异、命令摘要、适配器步骤、验证、回滚和证据。

- 全局提供操作记录页，每个资产、业务、策略、用户、事件和任务也提供本对象时间线。
- 支持按时间、操作者、来源、对象、动作、风险、结果、业务、站点和追踪ID筛选。
- 失败、取消、跳过、补偿、回滚、状态未知和外部变更必须保留，不能只展示成功动作。
- 操作详情显示变更前后和实际读回，不以用户提交值冒充设备生效值。
- 允许复制深链接和导出脱敏证据包，但禁止直接重放旧命令。
- 查询、查看敏感详情和导出本身也显示在操作记录中。
- 页面刷新、断线和跨设备登录后，从服务端恢复同一条时间线。

# 系统闭环

## 精准分流闭环

```text
流量与DNS观测
→ 识别业务和上下文
→ 规则决策
→ 选择合格出口
→ 建立连接
→ 验证业务结果
→ 更新节点业务能力
→ 发现误分流时生成纠正规则草案
→ 仿真和审批
→ 灰度发布
```

闭环结束条件：命中规则可解释、实际出口符合策略、业务验证通过、没有新增异常。

## 节点健康闭环

```text
基础探针
→ 协议探针
→ 业务探针
→ 历史稳定性评分
→ 进入候选或隔离
→ 小流量验证
→ 正式使用
→ 持续评估
```

防止闭环震荡：失败阈值、恢复阈值、冷却时间、最短保持时间、切换预算和人工锁定必须同时生效。

## DNS闭环

```text
查询观测
→ 选择解析路径
→ 返回地址
→ 关联真实连接
→ 验证实际出口和业务结果
→ 识别污染、泄漏或路径不一致
→ 调整上游或策略
→ 灰度验证
```

DNS健康不能仅通过53或853端口可达判定，必须检查正确答案、响应时间、DNSSEC状态和最终业务结果。

## 订阅闭环

```text
抓取
→ 隔离保存
→ 格式识别
→ 安全检查
→ 节点归一化和去重
→ 节点改名映射
→ 能力测试
→ 生成变更报告
→ 审批或自动准入
→ 灰度加入节点池
→ 持续验证
```

订阅失败时继续保留上一份已验证版本，不允许空订阅覆盖生产节点池。

## 配置发布闭环

```text
编辑草稿
→ 校验
→ 仿真
→ 影响分析
→ 审批
→ 备份
→ 金丝雀
→ 分批扩大
→ 全量验证
→ 观察
→ 归档或回滚
```

## 故障处置闭环

```text
告警
→ 去重聚合
→ 关联业务和最近变更
→ 分级
→ 指派负责人
→ 止损
→ 根因验证
→ 修复
→ 恢复验证
→ 复盘
→ 改进任务
```

告警关闭不等于事故结束。只有受影响业务恢复、验证窗口通过且改进任务已分配，事故才能关闭。

## 证书闭环

```text
发现证书
→ 识别负责人和使用范围
→ 到期预测
→ 自动申请或生成续期任务
→ 预部署
→ TLS验证
→ 灰度替换
→ 全量替换
→ 撤销旧证书
→ 归档证据
```

## 身份与访问闭环

```text
访问申请
→ 身份和设备姿态验证
→ 风险评估
→ 审批或策略授权
→ 发放短期凭据
→ 访问与会话审计
→ 到期撤销
→ 异常访问复核
```

## 容量闭环

```text
容量采集
→ 趋势预测
→ 风险阈值
→ 扩容或优化建议
→ 预算确认
→ 执行
→ 性能验证
→ 成本复核
```

## 灾备闭环

```text
生成备份
→ 完整性验证
→ 异地保存
→ 定期恢复演练
→ 对比RPO和RTO
→ 修复缺口
→ 再次演练
```

未经过恢复演练的备份不得显示为“可恢复”。

## 合规闭环

```text
资产和数据发现
→ 分类分级
→ 控制要求映射
→ 持续检查
→ 发现偏差
→ 整改任务
→ 验证
→ 形成报告和证据包
```

# 自适应设计

## 角色自适应

系统根据角色调整默认首页、术语和操作深度，但不隐藏用户有权访问的重要风险。

| 角色 | 默认视角 | 主要动作 |
| --- | --- | --- |
| NOC值班 | 实时态势、告警、受影响业务 | 确认、指派、止损、升级 |
| 网络管理员 | 站点、线路、路由、节点和DNS | 仿真、切换、发布、回滚 |
| 安全管理员 | 身份、风险、异常访问和策略 | 阻断、隔离、授权、审计 |
| 应用负责人 | 自己的应用、SLO和访问路径 | 验证、提出变更、查看影响 |
| 审批人员 | 风险、差异、影响和恢复方案 | 批准、附条件批准、拒绝 |
| 审计人员 | 证据、变更、访问和合规状态 | 查询、导出、复核 |
| 平台管理员 | 全局健康、容量、集成和升级 | 配置平台、治理适配器 |

## 规模自适应

- 少量对象直接显示。
- 大量对象自动分组、聚类和摘要。
- 超大规模默认显示异常和变化，不加载全部明细。
- 表格使用服务端分页、筛选和虚拟滚动。
- 拓扑按层级和视窗加载，避免一次渲染全部边和节点。

## 设备自适应

- 大屏：全局态势、轮播和只读演示模式。
- 桌面：完整操作、批量任务和多面板对比。
- 平板：现场巡检、任务确认和有限操作。
- 手机：告警确认、审批、只读状态和紧急操作；复杂配置引导到桌面。

响应式设计不等于缩小桌面页面。不同设备应保留适合当前场景的核心任务。

## 网络自适应

- 弱网时减少动画和实时刷新频率。
- 使用增量事件和本地缓存快照。
- 显示最后成功更新时间和数据是否过期。
- 连接中断时禁止提交未知结果的重复操作。
- 恢复连接后先读取服务端真实状态，再恢复界面。

## 健康状态自适应

- 正常时突出趋势、优化和容量。
- 退化时突出影响、近期变化和建议。
- 重大事故时进入事件模式，隐藏无关功能并固定事故时间线。
- 恢复后进入观察模式，显示剩余风险和验证倒计时。

## 权限自适应

无权限的动作不应仅显示一个失败按钮。系统应说明缺少的权限、可申请的角色、审批人和申请入口，但不得泄露无权查看的对象详情。

## 经验自适应

- 新用户显示向导、术语解释和安全默认值。
- 熟练用户支持命令面板、快捷键、批量操作和保存视图。
- 专家模式允许查看原始配置和协议细节。
- 用户选择可以保存，但不得自动改变安全门禁和审批要求。

# 人性化交互细节

## 全局上下文条

所有页面顶部固定显示：

- 当前集团或租户。
- 当前环境。
- 当前时间范围。
- 当前配置版本。
- 数据更新时间。
- 是否处于变更冻结或重大事故状态。
- 当前身份和权限范围。

切换租户、环境或时间范围时，页面内容必须整体更新，不允许部分组件保留旧上下文。

## 搜索与命令中心

统一搜索支持站点、设备、用户、应用、IP、域名、策略、节点、事件、配置版本和任务。

搜索结果同时显示对象类型、所属租户、状态、位置和可执行的安全动作。命令中心支持自然语言查找，但执行变更仍进入标准任务工作台。

## 列表和批量操作

- 默认列针对角色优化。
- 用户可以保存个人视图和团队视图。
- 批量操作前显示实际目标数量和被排除对象。
- 大范围操作必须允许下载目标清单。
- 部分失败后可以仅重试失败对象。
- 筛选条件、排序和分页在返回页面后保持。

## 表单

- 先选择目的，再展示必要字段。
- 提供模板、安全默认值和实时校验。
- 错误信息紧邻字段，并说明如何修复。
- 离开未保存表单前提醒。
- 长表单支持分步保存和稍后继续。
- 高级字段折叠，但被默认值影响的结果必须可见。

## 差异视图

差异同时提供三层表达：

1. 业务影响摘要。
2. 对象和字段级变化。
3. 原始配置差异。

删除、权限扩大、默认路由和DNS变更使用明显风险标记，不能只依靠红色。

## 确认与撤销

- 无风险操作直接完成并提供撤销。
- 中风险操作显示范围、影响和回退方式。
- 高风险操作要求输入变更原因并完成审批。
- 不使用模糊的“确定/取消”，按钮使用“开始灰度”“回滚到版本23”等具体文字。

## 状态反馈

任何点击后在100毫秒内提供视觉反馈。超过1秒显示进度状态；超过10秒显示正在执行的步骤、预计剩余阶段和离开页面后的行为。

## 空状态

空状态区分：尚未配置、没有权限、筛选无结果、数据加载失败、数据已过期和功能未授权。每种空状态提供相应下一步，不用同一个“暂无数据”。

## 错误状态

错误信息必须包括：

- 发生了什么。
- 是否产生了实际变更。
- 当前系统处于什么状态。
- 用户现在可以做什么。
- 自动恢复是否正在进行。
- 证据和支持编号。

# 信息架构与页面闭环

## 全球网络态势

目标：发现异常并进入处置闭环。

核心区域：全局SLO、错误预算、拓扑、告警、受影响业务、最近变更、AI分析和待办任务。

闭环入口：从异常节点、线路或业务直接创建事件、查看路径、启动诊断或进入关联变更。

## 组织、站点与设备

目标：管理资产生命周期和实际状态。

闭环：发现、准入、配置、基线校验、运行监控、漂移处理、迁移和退役。

## 节点、线路与隧道

目标：确保连接能力、质量和冗余真实有效。

闭环：接入、检测、评分、选用、隔离、恢复、容量评估和退役。

## 应用入口与反向代理

目标：从应用视角管理入口、后端、证书、策略和SLO。

闭环：发现应用、建立入口、配置安全和流量策略、灰度、业务验证、持续监控。

## 精准分流策略中心

目标：创建可解释、可验证、可回滚的分流策略。

闭环：需求、规则、冲突分析、仿真、审批、灰度、命中验证和误分流纠正。

## DNS、DHCP与IPAM

目标：保持名称、地址、租约和实际路径一致。

闭环：地址规划、解析配置、上游选择、查询观测、泄漏检测、故障切换和回收。

## 零信任与身份

目标：让正确的身份在正确条件下访问正确应用。

闭环：身份建立、姿态验证、授权、短期凭据、会话审计、撤销和复核。

## 可观测与事件

目标：从信号到事故恢复形成统一时间线。

闭环：采集、关联、告警、响应、恢复、复盘和改进。

## 自动化与修复

目标：安全执行重复任务并减少人工干预。

闭环：触发、预检、授权、执行、验证、回滚和效果评估。

## AI智能中心

目标：解释、辅助判断和生成受控处置草案。

闭环：问题、证据、推理、反证、建议、确定性校验、授权执行和结果反馈。

## 发布、版本与变更

目标：管理所有配置从草稿到生产和恢复的生命周期。

闭环：草稿、校验、审批、灰度、全量、观察、归档或回滚。

## 审计、合规与报表

目标：持续证明系统符合要求，而不是临时拼接材料。

闭环：要求映射、控制检查、偏差、整改、验证和证据包。

## 容量、成本与许可证

目标：提前发现容量和预算风险。

闭环：采集、预测、建议、预算、扩容、性能验证和成本复核。

## 系统、插件与集成

目标：管理平台自身、适配器、外部系统和升级风险。

闭环：安装、准入、权限、兼容性、运行健康、升级、回退和退役。

# 关键用户流程

## 新站点接入

1. 选择站点模板并填写业务目标。
2. 系统检查地址冲突、设备能力、线路和凭据。
3. 生成站点拓扑和建议配置。
4. 用户确认管理网、业务网、DNS和出口。
5. 在Shadow模式发现资产和采集基线。
6. 运行连接、DNS和业务测试。
7. 生成影响报告和接管计划。
8. 小范围终端灰度。
9. 扩大接管范围。
10. 验证站点SLO并归档接入报告。

## 创建业务分流

1. 选择或新建业务。
2. 输入域名、IP、应用或已有连接样本。
3. 系统识别重复规则和建议业务分类。
4. 选择默认策略、DIRECT、REJECT、节点池或固定出口。
5. 系统展示DNS、IPv4、IPv6和回退行为。
6. 用历史流量和测试集进行仿真。
7. 展示新增命中、改变命中和意外影响。
8. 选择灰度范围和观察时间。
9. 审批并执行。
10. 观察真实命中和业务结果。
11. 成功后全量；异常则自动回滚。

## 处理“网站偶尔打不开”

1. 用户输入网站或从失败连接发起诊断。
2. 系统收集终端、DNS、路由、节点、TLS、HTTP和最近变更证据。
3. 区分局域网、DNS、代理、运营商、目标站和账号问题。
4. 对比正常与失败时间窗口。
5. 给出已确认事实、可能原因和未知项。
6. 生成低风险验证动作。
7. 必要时隔离问题节点或撤销最近变更。
8. 重放真实业务探针。
9. 观察恢复稳定性。
10. 形成事件记录和预防措施。

## 节点池故障转移

1. 探针发现退化并进入观察状态。
2. 验证是否为单探针误报。
3. 检查备用节点的业务能力、故障域和容量。
4. 计算现有会话影响。
5. 新连接逐步转移，旧连接排空。
6. 验证业务成功率和SLO。
7. 原节点进入隔离和恢复探测。
8. 满足恢复阈值后小流量回归。
9. 观察稳定后恢复候选资格。

## 紧急回滚

1. 从事件、任务或版本页启动回滚。
2. 系统确认目标版本仍兼容当前环境。
3. 显示回滚会撤销和不会撤销的内容。
4. 验证备份和凭据。
5. 冻结新的冲突发布。
6. 按依赖逆序回滚。
7. 读回实际状态。
8. 运行关键业务验证。
9. 恢复成功后继续观察；失败则升级重大事故。

# 防止闭环失控

## 防自动化震荡

- 相反动作之间设置冷却时间。
- 同一对象单位时间设置动作预算。
- 状态变化需要连续证据。
- 发生频繁切换时自动转人工锁定。
- 多个自动化竞争同一对象时只允许租约持有者执行。
- 自动动作使用幂等键和明确终止条件。

## 防错误扩大

- 所有动作先确定最大影响范围。
- 默认从单对象或小批次开始。
- 关键指标恶化立即停止扩大。
- 回滚能力不可用时禁止高风险发布。
- 观测数据不足时不允许系统推断成功。

## 防学习污染

系统学习只调整建议权重和检测基线，不直接改变安全规则、审批条件和关键业务出口。学习样本必须关联真实结果，可被人工排除和回退。

# 通知、协作与交接

## 通知分级

- 信息：无需处理，仅记录。
- 提醒：需要关注但不紧急。
- 警告：需要在规定时间内处理。
- 严重：立即响应并建立事件。
- 灾难：启动重大事故和管理层通知。

同一根因产生的多个告警应聚合为一个事件，避免通知风暴。

## 任务交接

交接内容包括当前结论、已完成动作、未完成动作、风险、下一检查时间、所需权限和关键证据。接收人确认后责任才转移。

## 审批体验

审批页面只突出审批所需内容：目的、差异、风险、影响、灰度、验证和回滚。审批人可以批准、附条件批准、退回修改或拒绝；不能在不了解范围时一键批准。

# 无障碍与一致性

- 所有功能支持键盘访问和清晰焦点。
- 状态不能只依靠颜色表达，同时使用图标、文字和线型。
- 支持减少动画和高对比模式。
- 图表提供文本摘要和可访问数据表。
- 重要操作区域满足触摸尺寸要求。
- 同一动作在不同页面使用一致名称、位置和反馈。
- 时间统一显示时区并允许查看原始时间。
- 数值显示单位、采样窗口和数据来源。

# 闭环验收标准

## 完整性

每个关键流程必须回答：谁触发、用什么证据、谁决定、执行什么、如何验证、失败如何恢复、结果如何审计、经验如何沉淀。

## 可用性

- 新用户可以在引导下完成常见任务。
- 专家可以通过快捷入口减少重复步骤。
- 用户离开再返回后能恢复任务上下文。
- 页面刷新、弱网和浏览器关闭不会造成重复执行。
- 系统能明确区分成功、观察中、部分成功、回滚和未知状态。

## 安全性

- 未授权用户无法通过前端隐藏、API调用或任务重放越权。
- 高风险操作有审批、备份、灰度、验证和回滚。
- AI无法绕过确定性门禁。
- 自动化不能无限重试或反复切换。

## 可恢复性

- 每个生产变更存在可用回滚点。
- 回滚经过真实业务验证。
- 状态未知时先读取实际状态，不重复执行。
- 控制面故障不会立即中断现有数据转发。

## 可解释性

- 规则命中、节点选择、告警归因和自动修复都有证据。
- 推测与事实分开显示。
- 证据过期、矛盾或缺失时明确提示。

## 闭环退出条件

闭环只有在以下条件全部满足时才能标记完成：

1. 目标结果已达到。
2. 技术验证通过。
3. 业务验证通过。
4. 观察窗口结束。
5. 未产生新的高风险异常。
6. 实际状态与期望状态一致。
7. 审计证据完整。
8. 后续改进已完成或已明确指派。

# 体验度量

系统持续统计：

- 完成任务所需步骤和时间。
- 首次成功率。
- 用户返回修改次数。
- 误操作和撤销次数。
- 发布失败和回滚率。
- 告警确认与恢复时间。
- 自动修复成功率和人工接管率。
- 用户因信息不足而放弃的流程。
- 过期证据导致的重新检测次数。
- 不同角色的核心任务完成率。

体验指标用于发现流程问题，不用于惩罚个人。

# 设计进入界面阶段的门槛

1. 确认统一闭环模型和闭环退出条件。
2. 确认14个一级页面和角色默认视图。
3. 确认关键用户流程及风险等级。
4. 确认自动修复等级和高风险操作清单。
5. 确认数据新鲜度、可信度和未知状态表达。
6. 确认桌面、平板、手机和大屏的任务边界。
7. 为每个关键页面准备正常、空、加载、错误、无权限、弱网和事故状态。
8. 完成页面流转图后再生成全套高保真界面。
9. 界面能够区分补偿中、回滚失败、救援模式、无AI模式和状态未知。
10. 临时例外、人工锁定、独立验证来源和审计链健康具有可见入口。
11. 刷新、断线、多人编辑和跨入口提交不会造成重复执行或旧版本覆盖。
12. 自治暂停、当前任务安全停止和紧急冻结具有不同语义与恢复路径。
13. 全局和对象级操作记录覆盖人工、AI、自动化、API、CLI和外部漂移。
