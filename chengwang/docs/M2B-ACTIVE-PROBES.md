# M2b 主动路径与业务探针

## 1. 当前状态

M2b 分阶段交付，不能把“代码存在”“候选通过”和“生产验收”混为一谈：

| 阶段 | 内容 | 当前状态 | 当前可声明的结论 |
|---|---|---|---|
| M2b-0 | 本地模型、许可目录、安全拨号、分类、调度和独立存储的确定性测试 | `implemented+tested local-only` | 仅证明实现边界和本地故障分类；未部署 |
| M2b-1 | 独立容器、自有无副作用目标、固定出口、候选故障注入 | `design-only` | 完成后也只证明该探针位置和当前出口路径 |
| M2b-2 | 经业务负责人批准的少量公共目标，生产 Shadow 长期观察 | `design-only` | 完成后也只证明版本化业务契约，不证明全部节点或完整交易 |

M2a 已在生产灰度并通过初始门禁，但 24 小时浸泡尚未签署。M2b 不得越过这一生产前置条件。

M2b-0 当前只存在于 `internal/probe` 包，没有命令入口、HTTP API、容器、定时生产任务或控制面挂载，也没有访问任何公网业务。它不能被称为候选部署、生产探针或节点能力验证。

## 2. 不可突破的边界

- 执行器只接收 `targetId`，不提供任意 URL、主机、端口、Header、Body 或“立即运行”接口。
- 目标来自严格、版本化、只读目录；v1 只允许 HTTPS GET、443 端口和有界匹配器。
- 执行器无 Mihomo Controller 令牌、无 Docker socket、无生产数据卷、无控制面身份。
- 独立 bridge 网络、非 root、只读根目录、丢弃全部 capability，并限制 CPU、内存和 PID。
- 应用安全拨号器与独立出口策略必须同时生效。解析器必须返回从原主机开始的完整、有界 CNAME 链，链上每个别名都在目录中显式批准；全部 A/AAAA 通过特殊地址校验后固定单个 IP 建连并保留原 SNI。标准库只返回最终 CNAME，不满足该接口，因此进入 M2b-1 前仍需实现固定可信解析器。仅依靠应用校验不构成完整 SSRF 防护。
- 禁止重定向、Cookie、环境代理、跳过 TLS 校验、HTTP/2 跨目标复用和无限正文。
- 不登录、不支付、不交易，不使用真实账号凭据，不发起任何有副作用操作。
- M2b 只观察，不调用控制服务，不切 selector，不修改 DNS，不重载 OpenClash，不自动修复。
- 公共业务目标原则上必须有非空合同标记；仅状态码合同需要单独审批，不能自动从“2xx”推导完整业务可用。

## 3. 事实模型

主动探针和被动 Controller 观测并排展示，不合成为“节点健康”总绿灯。每条结果至少包含：

- 运行 ID、探针 ID、目录摘要、agent 与路径 ID；
- 发起、完成、过期时间和各阶段耗时；
- 结论、结果类别、独立性等级、证据引用；
- `advisoryOnly=true`。

结果不得保存 URL、解析 IP、响应正文、Cookie、Authorization、完整响应头或代理凭据。通过固定代理发起 HTTPS 时，本地 `httptrace` 不能证明目标 DNS；这类 DNS 必须显示 `not_measured`，不能从 HTTP 状态猜测。

结论至少区分：

- `available`：2xx 且版本化合同标记匹配；
- `indeterminate`：证据不足、合同不匹配、403、429、5xx、过期或探针自身异常；
- `unavailable`：只在相同路径连续达到批准阈值后成立，且不能扩大成全局结论。

业务结果类别区分 `auth_restricted`、`region_restricted`、`rate_limited`、`service_failure`、`contract_mismatch`、`tls_failure`、`timeout` 等。403/429 不计入节点连接失败次数。

## 4. 初始硬预算

- 每目标间隔至少 30 秒，业务目标默认 5 分钟并带确定性 jitter；
- 单次总超时不超过 10 秒；
- 全局并发 2，每探针和每目标主机并发 1；
- 有界队列，队满时跳过并计数，不积压补跑；
- 全局启动速率和响应字节均有固定预算；
- HTTP 正文最多读取 64 KiB；
- 429 遵守受限的 `Retry-After`，不得立即重试；
- 时间回拨冻结新鲜度和调度，不形成追赶式请求风暴。

## 5. 存储与 API 边界

probe-agent 是独立 spool 的唯一写入者。它使用不可变小段、临时文件原子替换、文件与目录同步、跨进程单写锁、总条目和总字节硬上限。损坏段原样保留；清理或同步失败时停止接受新结果并显示存储降级。

控制面只读挂载 spool，拒绝未知 schema、目录摘要不符、未来时间、过期和重复结果。匿名状态接口只能返回常量成本的去敏聚合；最多 200 条的明细接口必须先经过管理认证、范围和 TLS/回环门禁，再访问磁盘。M2b 不提供写 API。

上述控制面挂载和 HTTP 接口仍是 M2b-1/2 的门禁，不是 M2b-0 已实现能力。M2b-0 已实现的是独立文件 spool、严格 reader 和去敏聚合函数。跨重启启动预算目前只能从已落盘结果恢复；候选阶段还需要独立耐久的“已启动但未产出结果”记录。

## 6. 验收分层

进入候选前必须通过本地确定性测试：严格目录解析、SSRF/重绑定、固定 IP 与 SNI、重定向、TLS、正文上限、200/403/429/5xx、取消、无重叠、有界队列、时钟回拨、单写锁、损坏/目录洪泛、过期/重复和去敏 API。

候选必须证明容器隔离、唯一允许出口、资源上限、优雅停止和回滚，同时证明 OpenClash 配置、selector、DNS 和控制面哈希未改变。

- 24 小时只签“运行安全与初始门禁”；
- 7 天只签“调度和资源初步稳定”；
- 至少 30 天且有人工标注事件，才可讨论业务语义误报/漏报；
- 这些证据都不能推出 `99.999999%` 端到端可用率。

## 7. 未来的节点级能力评估

当前默认出口探测无法无扰证明每个订阅节点。节点级评估需要独立 Mihomo sidecar 或专用监听器，让每个固定路径拥有可证明的出口身份，并继续与生产 selector 隔离。没有该数据面时，界面和 API 必须使用“当前路径/业务观测”，不得使用“节点能力已验证”。
