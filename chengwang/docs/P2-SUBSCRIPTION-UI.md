## 当前状态与设计方向

本文件随候选代码先落盘；候选编译、单元 CI 和真实浏览器验收必须分别记录，不能把计划的测试数量写成通过数量。既有 P1 双浏览器证明探针页面，不证明本页。P2-05b 独立后端实验仍是独立回归，不往它的固定 46 次 API 捕获中追加 UI 写入后冒充原实验。

设计方向为“可信、清晰、操作有据”。保留原有导航与顶部任务栏，不重做外壳。首屏先解释当前会话、范围、写门和“本地准入、尚未发布”的边界；连接后才读取真实来源。来源、候选与节点分层显示，节点始终保留 `unknown`，不把导入数或接纳状态当成延迟、速度或业务可用性。写入前给出来源、版本和动作的明确确认；回退另加确认。网络错误保留旧数据并标旧，未知写结果引导查回执，不用重试按钮掩盖不确定性。文件内容和令牌只用于内存会话，不进入日志、浏览器存储或公开截图。

视觉沿用现有蓝灰色企业后台，不引入外部字体、CDN、营销首屏或新组件依赖。界面与 React 技能影响了本轮的错误摘要焦点、标签、会话所有权、过期结果隔离、响应式和 reduced-motion 约束；这些约束尚须真实渲染验证。

## 接线与边界

- `订阅与提供者` 导航加载真实 `Subscriptions` 组件。导航离开仅隐藏，不卸载内存会话，避免遗失正在查证的命令；清除会话、编辑令牌或真正卸载才清理令牌、私有导入字节、请求与 intent。
- 新增只读 `GET /api/v1/subscriptions/access` 与 `/sources/{sourceId}/access`。它们提供当前范围、独立权限、有效写门及安全策略引用目录；不证明来源存在、已批准或节点健康。API 与 service 仍逐次授权每个写操作。
- 可选 `AccessReader`、`PolicyReferenceReader` 不改变旧必需 Backend 接口。目录只输出 `referenceId/revision`，最多 32 项，CPU-only；不读取私有库、不调用 `Describe/Fetch`，不输出 URL、CA、密钥或 secretVersion。
- 页面覆盖当前后端的创建、文件导入、批准、Fetch、本地接纳、拒绝、回退，以及候选/节点修订围栏分页和耐久回执。YAML、URI、base64 为显式格式选择，不靠节点名称猜订阅数量。
- 批准只使用服务端安全目录。抓取分为“本会话已读回批准”和“交接批准ID（未核验）”两个明确模式，不互相回退或覆盖。交接模式独立填写批准 ID 与策略版本，确认框展示 source ID、来源修订、批准 ID、策略版本，并明确实际目录引用未读回、由批准 ID 决定；准备新批准的目录下拉框不绑定本次交接抓取。Fetch 仍由服务端重新验证，不允许操作者越权读取批准者的私有命令回执。切换引用/修订后旧批准不能冒充新批准。
- 目前没有任意 URL、私有 CA 或凭据目录编辑器。新增/变更服务器私有来源目录仍需管理工作流；这是产品缺口，不伪装成“所有订阅设置都已可视化”。

## 失败与恢复约束

请求仅同源 HTTPS，包括回环地址；禁止重定向、跨源凭据和自动 POST 重试。客户端对流字节、UTF-8、JSON 重复键/深度/节点数、安全整数及 DTO 未知字段分别检查；整请求有固定 30 秒上限，页面交互还可更早取消等待。取消等待不表示服务端取消。

一次明确操作只创建一次高熵幂等 intent。导入字节保存在私有 WeakMap，不出现在公开 intent 元数据。POST 发出后的中断或无法校验的响应一律按“可能已改变”处理。已有命令 ID 时只读查证；无 ID 时明确不能自动确定结果，不生成新键重复提交。无关回执不得解锁另一个未决命令。页面的角色提示不替代服务端授权；写门关闭仍可读。

来源、权限范围、候选修订或节点修订变化时不得合并旧页。旧请求完成不得覆盖新会话、新来源或新修订。409 应重新读取当前状态，不自动重做写入。网络故障不能虚称“令牌未发送”，旧库存也不能继续标为新鲜。

## 首轮实际运行与修正候选
