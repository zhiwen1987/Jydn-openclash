# 澄网企业级闭环补强方案 v2.1

## 文档状态

- 性质：设计基线与实现约束，不代表功能已经开发或通过生产验收。
- 基线日期：2026-10-18。
- 目标：补齐平台自身、跨系统、极端恢复、外部依赖、数据治理、交互和人员失联场景的闭环。
- 关联文档：[功能基线](FUNCTIONAL-BASELINE-v1.0.md)、[操作与系统闭环](UX-AND-CLOSED-LOOPS-v1.0.md)、[自治运维](AUTONOMOUS-OPERATIONS-v2.0.md)。

本方案中的“闭环”不等于没有故障，而是系统面对正常、异常、部分失败、证据矛盾和自身失效时，都能进入确定状态，限制影响，保留证据，并能够恢复或明确交接。

# 统一闭环契约

任何关键能力都必须实现以下环节：

```text
触发与观测
→ 数据质量判断
→ 识别对象、依赖和负责人
→ 形成事实、假设、反证和未知项
→ 生成方案并计算影响
→ 权限、预算和安全门禁
→ 幂等执行或只读调查
→ 独立技术与业务验证
→ 提交、补偿、回滚或安全降级
→ 不可抵赖审计和结果交接
→ 复盘、学习、到期复核或退役
```

缺少任一环节时，不得显示“完成”。系统只能显示：等待证据、等待授权、观察中、部分成功、补偿中、回滚中、救援模式、等待人工或未知。

## 通用闭环对象

每个闭环实例至少包含：

- 稳定对象ID、租户、站点、业务、负责人和重要等级。
- 期望状态、实际状态、状态版本和最近读回时间。
- 触发原因、证据、反证、未知项及数据新鲜度。
- 依赖图、故障域、影响范围和受影响SLO。
- 方案、风险、权限、审批、预算、变更窗口和停止条件。
- 幂等键、执行步骤、补偿步骤和恢复点。
- 技术验证、业务验证、观察窗口和外部验证结果。
- 最终状态、残余风险、人工交接、审计锚和复盘任务。
- 生效时间、到期时间、复核时间和退役条件。

## 通用关闭条件

1. 期望状态与实际状态完成读回对账。
2. 真实业务验证通过，观察窗口内没有复发或新增异常。
3. 补偿、回滚或降级路径已验证可用。
4. 证据完整、时间可信、审计写入独立存储。
5. 未完成事项、残余风险和负责人已经明确。
6. 临时策略、例外和恢复资源均有到期或清理计划。

# 十二项闭环补强

## 1. 平台自身升级与迁移

```text
发现版本
→ 校验来源、签名、SBOM和漏洞状态
→ 计算控制器、数据库、适配器和数据面兼容矩阵
→ 备份并做恢复预演
→ 数字孪生回放
→ 先扩展兼容结构
→ 金丝雀控制器
→ 混合版本读写验证
→ 分批切换
→ 观察任务、审计、租约和适配器
→ 最后收缩旧结构
→ 归档或回滚
```

约束：

- 数据库迁移采用扩展、兼容、最后收缩的顺序。
- 新旧控制器并存时必须定义唯一写入者和最低协议版本。
- 降级前验证新版本没有写入旧版本无法理解的数据。
- 迁移脚本必须幂等，能够从中断点继续或安全撤销。
- 控制面升级失败不得影响数据面最后稳定配置。

验收覆盖成功升级、断电、迁移失败、混合版本、适配器不兼容和降级恢复。

## 2. 跨设备和跨系统事务

路由器、DNS、代理、证书、防火墙和外部系统不能假设具有数据库式原子事务。每次变更生成ChangeSet和依赖图，每一步必须具有：前置版本、幂等键、超时、重试上限、实际状态查询、成功条件、失败条件、补偿动作和不可补偿标记。

```text
规划
→ 锁定目标版本
→ 建立恢复点
→ 按依赖顺序执行
→ 每步读回确认
→ 失败时停止扩大
→ 判断已完成步骤能否保留
→ 逆序补偿或整体回滚
→ 对账所有参与系统
→ 真实业务验证
→ 提交或人工恢复
```

- 超时不等于失败，必须先查询实际状态。
- 状态未知时禁止重复执行非幂等动作。
- 补偿本身也是正式任务，接受预算、审计和验证。
- 不可补偿步骤置于最后，并要求更高审批级别。

验收在每一步注入断网、超时、重复回调、控制器重启和设备重启，确保不存在重复签发、重复删除、旧版本覆盖新版本或虚假完成。

## 3. 回滚失败与系统生存

```text
原动作失败
→ 原地补偿
→ 回滚最近稳定版本
→ 切换独立恢复点
→ 启用最小救援配置
→ 冻结自动写入
→ 保留带外管理和证据通道
→ 黑启动重建控制面
→ 重新发现并对账数据面
→ 小范围恢复业务
→ 分批恢复自治
```

最小救援配置不是绕过策略，只包含经过审批的基础管理连接、必要DNS、本地管理入口、审计投递和明确允许的关键业务路径。它必须离线保存、签名、加密、定期演练，并与主数据库和AI服务解耦。

黑启动按信任根、数据库、审计、资产、适配器、只读观测、单一写入者、验证器和自动化的顺序恢复。任何一层不可信时，后续写入能力不得开放。

验收覆盖主库不可用、全部控制器失效、回滚包损坏和管理网络中断。

## 4. 外部供应商和不可控依赖

代理供应商、订阅源、运营商、云服务、DNS、证书机构、通知渠道、许可证服务和目标业务必须登记：负责人、合同、SLA、地区、数据范围、配额、维护窗口、故障域、退出条款、导出方式和备用方案。

```text
独立健康和SLA观测
→ 排除本地配置、账号和配额问题
→ 计算业务影响和错误预算
→ 选择降级、备用供应商或等待
→ 非关键业务灰度切换
→ 验证故障域独立性和真实业务
→ 保持、回切或人工升级
→ 形成供应商绩效和退出证据
```

- 自动化不得购买服务、修改合同或接受新的合规风险。
- 名称不同但共用ASN、机房、上游或账号体系的服务不得视为独立备用。
- 目标网站风控、账号限制和供应商内部原因无法确认时保留未知状态。

## 5. 数据隐私生命周期

```text
数据发现
→ 分类分级和目的登记
→ 最小化采集
→ 采集前脱敏
→ 按驻留区域存储和处理
→ 基于用途授权
→ 持续审计
→ 到期冻结
→ 主存储和派生数据删除
→ 备份到期清除
→ 删除证明
```

- 默认不采集正文、账号凭据、完整URL参数和无关个人数据。
- 探针响应正文只保留判定所需摘要、结构化结果或受控样本。
- AI只能访问经过授权和脱敏的最小上下文。
- 删除覆盖索引、缓存、搜索副本、向量库、报表和到期备份。
- 审计保留与隐私删除冲突时保留不可逆摘要，不保留原始敏感内容。

验收验证删除后不能从搜索、报表、AI检索或旧缓存重新获得数据。

## 6. 审计证据完整性

关键审计事件采用追加写入、序列号、前一事件摘要、当前摘要、签名身份和可信时间，并异步复制到独立不可变存储。业务管理员不能修改或删除独立审计副本。

```text
产生事件
→ 本地持久队列
→ 摘要和签名
→ 主审计流
→ 独立不可变存储
→ 校验连续性、签名和时间偏差
→ 发现缺口或篡改
→ 冻结高风险自动化
→ 保存现场并创建安全事件
→ 修复后补传和重验
```

- 设备时间异常时同时记录采集时间、接收时间和可信时间源。
- 审计队列具有容量上限和保护策略，不得静默丢弃。
- 审计完整性失效时冻结高风险发布、权限变更和删除。
- 证据包包含校验清单和独立验证所需元数据。

## 7. AI模型和知识生命周期

模型、提供商、提示模板、工具权限、知识库、检索策略、特征、阈值、评估集和安全策略均为独立版本对象。

```text
登记候选模型或知识
→ 来源、许可和敏感性检查
→ 离线准确性与安全评估
→ 提示注入、知识污染和对抗测试
→ 历史事故回放
→ Shadow运行
→ 与当前版本对比
→ 人工批准
→ 小范围启用
→ 持续监测质量、成本和漂移
→ 保持、降级、熔断或回退
```

- 输出必须通过结构、对象ID和确定性策略门禁。
- 检测无依据结论率、工具失败率、超时率、成本和结果漂移。
- 单一模型异常时切换已验证备用模型；全部不可信时进入无AI模式。
- 无AI模式保留规则引擎、探针、验证器、看门狗、审计和人工操作。
- AI不能修改自己的权限、评估标准、安全策略和审计记录。

## 8. 资产发现、准入与退役

```text
被动或主动发现
→ 临时指纹
→ 去重和合并候选
→ 识别租户、站点和负责人
→ 未知资产保持只读或隔离
→ 身份和风险检查
→ 人工确认准入
→ 建立基线、依赖和探针
→ 持续漂移与失联检测
→ 迁移、转交或退役
→ 撤销凭据、移除策略并保留审计
```

- 仅凭IP、主机名或MAC不得自动合并资产。
- 未知资产不得被自动安装代理、修改网络或获取高权限凭据。
- 失联与退役必须区分，失联不能触发自动删除。
- 退役前检查业务依赖、证书、隧道、DNS、策略和恢复要求。

## 9. 业务服务定义生命周期

每个业务服务必须定义负责人、用户范围、域名/IP/端口/协议/进程/SNI、重要等级、SLO、错误预算、数据分类、地区限制、固定出口、会话保持、技术探针、真实业务探针、路径约束、容量和依赖业务。

```text
提出业务意图
→ 识别范围和负责人
→ 生成匹配与路径草案
→ 冲突、遗漏和泄漏分析
→ 仿真和探针校准
→ 审批
→ 指定终端灰度
→ 真实业务验收
→ 持续SLO和误分流监测
→ 变更、暂停或退役
→ 清理规则、探针、凭据和数据
```

未定义真实探针或负责人的业务不得进入高自治等级；退役后不得留下仍能命中的幽灵规则。

## 10. 临时例外和人工锁定

临时直连、临时代理、绕过检查、固定节点、维护窗口、风险接受、紧急访问和告警抑制都属于例外。

```text
提出例外
→ 说明原因、范围、风险和替代方案
→ 指定负责人和审批人
→ 设置开始、到期和复核时间
→ 冲突与影响分析
→ 最小范围启用
→ 持续监测
→ 到期自动撤销或重新审批
→ 验证恢复原策略
→ 归档结果
```

- 禁止无到期时间的临时例外。
- 自动延期禁止；延期等同新审批。
- 到期撤销失败形成高优先级事件，并冻结同类新例外。
- 人工锁定在所有自动规划和修复界面显式可见。

## 11. 独立监测和外部验证

独立性等级：

- P0：与被测组件同进程，只用于开发。
- P1：不同进程但同主机。
- P2：不同主机但同站点、同出口。
- P3：不同站点或不同出口。
- P4：独立云区域、组织或外部监测服务。

关键业务至少使用两个不同故障域的验证来源，其中一个不得依赖主控制数据库、主DNS路径和主代理出口。

```text
调度探针
→ 验证探针身份、时间和网络路径
→ 执行技术与业务事务
→ 记录路径、出口和结果
→ 多视角聚合
→ 判断一致、矛盾或证据不足
→ 一致失败时创建事件
→ 矛盾时扩大取证但不宣布故障或恢复
→ 修复后独立复验
→ 持续检测探针偏差和失效
```

单个绿色探针不能覆盖真实用户失败，单个红色探针也不能直接触发大范围切换。

## 12. 管理员离线和管理权恢复

```text
检测管理员不可达或管理入口失效
→ 保持最后稳定数据面
→ 自治限制在批准的低风险动作
→ 高风险任务排队并安全降级
→ 独立渠道通知备用联系人
→ 必要时启用短时Break-glass
→ 建立带外管理连接
→ 验证身份、范围和审计能力
→ 接管或恢复主入口
→ 撤销临时权限
→ 复核离线期间全部动作
```

- 单人环境至少具备离线恢复材料和独立身份恢复路径。
- Break-glass不能依赖故障中的身份提供商或主数据库。
- 恢复材料加密、轮换并定期演练，不得保存明文凭据。
- 管理员离线不扩大系统权限，也不允许AI代替高风险审批。
- 没有备用人员时优先保持业务和证据，不尝试不可逆修复。

# 九项横切闭环

以下能力贯穿前述十二项，不作为孤立页面存在；任何一项失效都可能使其他闭环无法结束。

## 1. 密钥、凭据和证书

发现和登记、责任归属、到期预测、自动或人工申请、预部署验证、双版本并存、灰度轮换、旧凭据撤销、使用面清查和证据归档必须连续完成。轮换失败时保留旧凭据的时间必须受限，且不得把长期明文凭据写入任务、日志或备份。

## 2. 容量、背压和资源耗尽

采集、预测、限额、优先级、背压、负载削减、扩容、恢复和成本复核形成闭环。资源紧张时优先保证数据转发、DNS、身份、安全监督器、看门狗和关键审计；主动降低拓扑动画、普通日志、历史分析和非关键探针。消息积压和存储耗尽不得拖垮数据平面。

## 3. 通知送达和升级

事件产生、去重、路由、发送、送达回执、用户确认、超时升级、备用渠道、责任接收和关闭通知形成闭环。渠道返回成功不等于人已收到；高风险事件必须具有确认超时和备用联系人。通知风暴触发聚合和频率保护，但不能抑制新的重大影响。

## 4. 适配器和插件生命周期

登记来源、签名和SBOM、权限审查、协议兼容、沙箱测试、Shadow、灰度、运行健康、升级、熔断、回退和退役形成闭环。适配器异常时冻结其写入权限但保留可用的只读观测；插件不得直接持有超出声明范围的设备凭据。

## 5. 许可证和功能授权

许可证发现、用量、到期预测、宽限期、影响分析、续期任务、降级路径和恢复验证形成闭环。许可证服务不可达不得导致数据面立即停转；系统必须提前说明哪些功能会只读、降级或停止，并保留配置导出能力。

## 6. 时间正确性

发现时钟偏差、验证可信时间源、限制依赖精确时间的动作、修复同步、重新排序证据和恢复自动化形成闭环。大幅调时、时间回拨和不同站点时区不得破坏租约、证书、令牌、审计顺序和任务超时。

## 7. 可移植导出与恢复

配置、领域对象、策略、版本、审计索引和依赖关系必须支持带版本清单的签名导出。导入先进入隔离区，完成结构、兼容、安全和冲突检查，再由用户选择新建、合并或恢复。导出成功只有在隔离环境完成真实恢复后才能标记为“可恢复包”。

## 8. API客户端和Webhook

客户端登记、最小权限、短期凭据、配额、幂等、版本、弃用、轮换和撤销形成闭环。Webhook使用签名、时间戳、重放保护、投递ID、重试上限和死信队列；接收方失败不能无限重试，也不能因为响应丢失重复产生非幂等动作。

## 9. 操作记录和变更历史

选定的页面方向与详细交互见[操作详情与执行时间线交互规格 v2.1](OPERATION-DETAIL-INTERACTION-v2.1.md)。

审计链用于证明记录可信，操作记录用于让管理员理解、查询、交接和恢复，两者共享事件ID但不能互相替代。以下来源全部必须记录：

- Web、移动端、API、CLI和ChatOps发起的人工操作。
- AI生成的分析、建议、工具调用和被安全监督器拒绝的动作。
- 自动化、定时任务、修复剧本、协调器和看门狗动作。
- 适配器对设备、DNS、内核、证书和外部系统的实际调用。
- 审批、拒绝、撤回、暂停、取消、超时、补偿、回滚和人工接管。
- 读回发现的设备本地修改、外部系统修改和未知来源漂移。
- 敏感配置查看、凭据导出、证据导出和审计查询。

### 操作记录结构

每条操作记录至少包含：

- `operation_id`、`trace_id`、任务ID、步骤ID、父子关系和幂等键。
- 操作者真实身份、身份类型、代理身份、代表谁执行以及认证会话。
- 来源入口、来源地址、终端、租户、环境、站点和可信时间。
- 操作目的、原因、关联工单、变更窗口和风险等级。
- 目标稳定ID、目标数量、操作范围、当前版本和目标版本。
- 变更前摘要、变更后摘要、结构化差异和实际设备读回值。
- 权限判断、审批人、审批条件、安全监督器决定和预算消耗。
- 每一步开始、结束、输入摘要、输出摘要、重试、错误和状态。
- 技术验证、业务验证、稳定性观察、恢复点和最终结果。
- 残余风险、未完成事项、下一负责人和下一复核时间。

### 状态模型

```text
已请求
→ 预检中
→ 等待审批 / 已拒绝
→ 排队
→ 执行中
→ 验证中
→ 观察中
→ 成功且已验证
```

异常分支必须独立保留：已取消且未变更、部分成功、补偿中、已回滚、回滚失败、状态未知、外部漂移和人工接管。后续状态不能覆盖前序事件，只能追加新事件。

### 隐私和安全

- 密码、令牌、私钥、Cookie、完整授权头和敏感响应正文不得进入操作记录。
- 命令和配置按结构化字段脱敏；原始输出仅在必要时加密短期保存。
- 查看和导出操作记录也需要权限并产生新的操作记录。
- 删除策略只删除允许删除的详情，长期保留不可逆摘要、身份、对象、时间、结果和完整性证明。
- 记录写入失败时，高风险操作必须停止；低风险只读任务可以继续，但必须显著标记审计降级。

### 查询和交互

- 提供全局操作记录、对象时间线、用户时间线、任务时间线和事故时间线。
- 支持按操作者、来源、对象、动作、结果、风险、站点、业务、时间和追踪ID筛选。
- 每条记录先显示“谁因为什么对什么做了什么，最终怎样”，再展开技术步骤。
- 从记录可跳转到变更差异、审批、证据、验证、恢复点和关联事故。
- “重新执行”只能基于当前状态生成新草稿并重新预检，禁止直接重放旧命令。
- 导出生成带签名和校验清单的证据包，并遵守租户隔离、脱敏和保留策略。

### 验收

- 覆盖人工、AI、自动化、API、CLI、拒绝、取消、失败、回滚、状态未知和外部漂移。
- 页面刷新、控制器重启和网络断开后，时间线仍连续且不会重复记录同一步骤。
- 验证任何生产变更都能从业务对象追溯到操作者、原因、审批、实际设备结果和恢复点。
- 验证无法通过编辑主数据库、删除任务或更改系统时间伪造完整操作历史。

# 交互闭环复核与修复

本节基于现有自治控制中心概念图复核。静态图片只能验证信息结构，不能证明真实交互、键盘操作、弱网续接和并发安全已经实现。

## 1. “整体健康”容易制造虚假安全感

问题：单一百分比可能掩盖未监控资产、过期证据和关键业务异常。

修复：健康值旁始终显示监控覆盖率、证据新鲜度、未知盲区、最差关键业务和计算窗口。覆盖率不足时不允许显示绿色“整体正常”。

## 2. A3等自治等级不够直观

问题：用户无法仅凭“A3”理解系统现在能做什么。

修复：等级旁显示自然语言摘要，例如“可自动隔离单节点；全局DNS、默认路由和支付出口仍需审批”。点击后展示允许、禁止和最近自动动作。

## 3. “批准灰度”过于直接

问题：高风险事项在列表中直接批准，容易跳过证据和影响确认。

修复：列表只提供“审阅并决定”。详情页按目的、证据、差异、影响、灰度、验证、回滚和审批条件逐项展示，最后才能批准。

## 4. “暂停自治”语义模糊

修复为三个确定动作：

- 冻结新自动变更：正在验证的任务继续完成。
- 安全停止当前任务：在最近安全点停止并读回状态。
- 紧急停止：冻结所有自动写入，不停止现有数据转发。

按钮必须显示影响范围、预计结果、恢复方式和是否需要审批。

## 5. 页面刷新、断线和浏览器关闭

- 任务必须由服务端持久化，页面不是任务执行者。
- 重连后读取真实任务状态，不从本地进度动画推断。
- 状态未知时禁止重复点击，提供“重新读取目标”动作。
- 表单草稿自动保存，恢复时显示基于哪个版本和是否发生冲突。

## 6. 多人并发和跨入口冲突

- 对象显示当前编辑者、活动任务、租约和最近变更。
- API、CLI、Web和自动化共享版本前置条件和幂等模型。
- 旧页面提交时必须显示差异并要求重新合并，不得覆盖新版本。
- 审批人不能审批自己提交的高风险变更。

## 7. 进度不能伪精确

调查进度以阶段、已完成探针、预算消耗、最后证据时间和下一停止条件表达。没有可计算工作量时不得显示虚假的百分比或剩余分钟。

## 8. 拓扑信息过密

- 默认只显示与当前任务相关的路径和故障传播范围。
- 物理、DNS、代理、隧道、业务和变更影响作为独立图层。
- 悬停显示摘要，单击固定选择并打开详情，双击进入对象页。
- 提供可搜索的表格替代视图，所有拓扑操作支持键盘完成。

## 9. 状态不能只依赖颜色

正常、观察、异常、未知、冻结和恢复必须同时使用文字、图标、形状或纹理。错误信息说明发生了什么、影响什么、系统做了什么、用户还能做什么。

## 10. 人工收件箱需要责任闭环

每项只提出一个最小决策问题，包含截止时间、建议选择、替代方案、不处理的后果、所需权限和责任转移。指派后必须由接收人确认，原负责人才能解除责任。

## 11. 批量操作需要分层反馈

批量执行前显示总对象、符合条件、被排除和需要单独审批的数量。执行后按成功、失败、跳过、状态未知和已回滚分组，不用单一“部分成功”。

## 12. 移动端和大屏边界

- 移动端只允许查看、确认通知、低风险批准和紧急冻结，不承载复杂配置。
- 大屏只展示态势和事件，不提供高风险写操作。
- 完整仿真、差异、批量修改和回滚在桌面端完成。

## 13. 时间、时区和证据有效期

所有时间显示明确时区，并可查看原始设备时间、平台接收时间和可信时间。相对时间不能替代审计时间。过期证据必须显著标记，并阻止依赖它的自动动作。

## 14. 无障碍与认知负担

- 支持键盘、清晰焦点、屏幕阅读器标签、缩放和减少动画。
- 重要文字不低于可读字号，图表提供表格和文本摘要。
- 高压事故界面减少无关指标，只保留影响、当前处置、风险、停止和接管。
- 专业名词提供就地解释，但不遮挡关键操作。

# 缺失功能补齐与范围边界

## 平台原生必须具备

1. 企业身份：OIDC、SAML 2.0、LDAP/AD、MFA、WebAuthn、SCIM、会话撤销和Break-glass。
2. 权限治理：RBAC与属性条件、职责分离、临时授权、审批代理、定期权限复核。
3. 任务系统：持久任务、幂等、租约、暂停、取消、补偿、重试、超时和人工接管。
4. 配置即代码：版本化导入导出、结构校验、差异、签名、GitOps接口和双向漂移检测。
5. 通知值班：通知路由、去重升级、静默窗口、值班表、备用联系人、送达和确认回执。
6. 操作记录：人工、AI、自动化和外部漂移统一追踪，支持对象时间线、签名导出和恢复关联。
7. 统一搜索：资产、业务、域名、IP、规则、事件、任务、版本、操作记录和审计证据。
8. API治理：版本、认证、授权、限流、配额、幂等键、审计、Webhook签名和弃用策略。
9. 时间服务：NTP状态、时钟偏差、可信时间源和时间异常保护。
10. 数据治理：分类、脱敏、驻留、保留、导出、删除、删除证明和法律保留。
11. 国际化基础：时区、地区格式、中文主界面和可扩展多语言资源；不把文案写死在业务逻辑中。

## 通过适配器接入

1. 遥测：SNMP、Syslog、OpenTelemetry、Prometheus、NetFlow、sFlow和IPFIX。
2. 受控诊断：ICMP、TCP、TLS、HTTP、DNS、Traceroute和经审批的短时抓包；抓包默认脱敏并受时长、大小和权限限制。
3. 网络：BGP、OSPF、VRRP、策略路由、NAT、QoS和SD-WAN先只读观测，再按设备能力开放受控写入。
4. 企业系统：CMDB、ITSM、SIEM、SOC、IPAM、DHCP和资产目录。
5. 自动化：Ansible、Terraform、Git平台、CI/CD和企业作业平台。
6. 通知：邮件、短信、企业微信、钉钉、飞书、PagerDuty类值班平台和签名Webhook。
7. 安全：WAF、DDoS防护、IDS/IPS、EDR、NDR和云安全平台。
8. 云与网络厂商：通过版本化适配器接入，不在核心领域模型中写死厂商字段。

## 明确不重复自研

- 不自研完整身份提供商、SIEM、ITSM、CMDB、WAF或DDoS清洗引擎。
- 不自研通用数据库、消息队列、密钥管理系统和对象存储。
- 不承诺第一版覆盖所有路由协议、代理协议和厂商设备。
- 核心平台负责统一意图、治理、编排、验证、证据和安全边界，专业系统通过适配器提供执行能力。

# 实现顺序

## 阶段一：不可绕过的底座

统一对象和状态、稳定ID、版本前置条件、幂等键、读回对账、独立审计、安全监督器、停止开关、权限矩阵、恢复点和补偿契约。

## 阶段二：可信观测和业务契约

资产发现与准入、业务服务契约、SLO、真实探针、独立监测、外部供应商和依赖登记。

## 阶段三：受控执行和极端恢复

跨系统事务、灰度、补偿、回滚失败、救援配置、黑启动、平台升级和管理员离线演练。

## 阶段四：AI和学习

AI离线评估、历史回放、Shadow、模型熔断、无AI模式和经过验证的长期知识；按业务域逐级开放A3和A4，不开放无边界A5。

# 进入实现前的新增门槛

1. 十二类闭环均指定产品、技术和验收负责人。
2. 每类都有正常、异常、部分失败、状态未知和恢复用例。
3. ChangeSet、补偿动作和不可补偿动作完成契约评审。
4. 救援配置、带外接管和黑启动完成桌面推演。
5. 数据分类、驻留、保留、删除和审计冲突规则完成评审。
6. 审计不可变存储、签名、可信时间和独立校验完成评审。
7. AI评估集、对抗集、熔断、无AI模式和回退条件完成评审。
8. 独立监测至少包含两个故障域，并定义结论矛盾处理。
9. 临时例外具备强制到期、撤销验证和失败升级。
10. 自治交互覆盖刷新、弱网、多人冲突、状态未知和紧急停止。
11. 缺失功能完成“平台原生、适配器、明确不自研”归类和版本计划。
12. 操作记录字段、脱敏、保留、检索、导出和审计链关联完成评审。
13. 所有高风险闭环通过故障注入、恢复演练和证据审计后，才允许生产试点。
