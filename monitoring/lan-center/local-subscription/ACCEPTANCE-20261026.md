## 有意保留的验收边界

- 健康探测与普通 HTTP 场景使用回环源站，不代表 ChatGPT、Grok 等真实账号业务已经用真实自建节点验收。用户尚未提供这样的节点。
- 公共订阅一／两源测试在隔离环境执行，保留了公共准入与观察期门槛；没有为测试强制更新生产机场订阅。
- 旁路由采用热加载，未重启生产 OpenClash；生产容器亦未重建。持久挂载已核对，真实的整机／容器维护重启仍需在维护窗口复验。
- 验证了备份完整性、恢复脚本预检查与隔离故障恢复，没有为了验收再回退一遍生产环境。
- 单次线上灰度操作曾返回 HTTP 错误，首次取证只记录异常类型，未保留状态码和错误体，因此不归因为某个具体原因；后续相同请求成功，提交结果、健康入库及删除均有回读证据。当前工具已补充有界的错误码取证，不能把最初原因描述成已经查明。

部署过程还捕获并修正了无连接时 `connections: null`、精简 OpenWrt Ruby 缺少 tmpdir，以及测试对宿主机监听地址的错误假设；这些问题修正后才完成相应验收。
